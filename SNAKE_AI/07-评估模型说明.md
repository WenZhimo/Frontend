# 评估模型说明

## 入口脚本

```bash
python src/train/snake_nn/evaluate_models.py <path>
```

对应脚本：

```text
src/train/snake_nn/evaluate_models.py
```

---

## 它能做什么

这个脚本主要用于：
- 评估单个模型
- 评估某个目录中的一批模型
- 生成汇总报告
- 为模型管理页提供离线评估能力补充

它不会负责训练，只负责“跑模型并生成报告”。

---

## 两种常见用法

### 1. 评估单个模型

```bash
python src/train/snake_nn/evaluate_models.py artifacts/models/exports/pc/best-of-batch.json
```

适合：
- 你只想看某个模型的分数
- 你想复查某个候选模型
- 你想给默认模型单独生成报告

### 2. 评估一个目录

```bash
python src/train/snake_nn/evaluate_models.py artifacts/models/exports/pc
```

适合：
- 你想批量比较某个档位的候选模型
- 你想生成一份目录级汇总报告

---

## 评估时会统计什么

评估逻辑不是只看苹果数，它会综合多项指标。

每个 episode 里会统计：
- `score`：苹果数
- `frames`：存活步数
- `fitness`
- `survivalRatio`
- `approachAppleEvents`
- `repeatCellCount`
- `stallSteps`

然后聚合成：
- `avgSelectionScore`
- `avgFitness`
- `avgScore`
- `avgFrames`
- `avgSurvivalRatio`
- 对应标准差等

其中最核心的排序指标通常是：
- `avgSelectionScore`

---

## 输出位置

### 评估单个模型时
会生成：

```text
<model>.eval-report.json
<model>.eval-report.html
```

例如：

```text
artifacts/models/exports/pc/pc-3000-23-000.json.eval-report.json
artifacts/models/exports/pc/pc-3000-23-000.json.eval-report.html
```

### 评估整个目录时
会生成目录级汇总：

```text
artifacts/models/exports/<profile>/evaluation-report.json
artifacts/models/exports/<profile>/evaluation-report.html
```

---

## 和模型管理页里的评估有什么关系

### 命令行评估
你直接运行 `evaluate_models.py`，是显式离线评估。

### 管理页评估
管理页会通过本地服务调用评估逻辑。

管理页在“评估全部候选模型”时，除了档位目录下的报告，还会额外写：

```text
artifacts/models/exports/evaluation-report.json
artifacts/models/exports/evaluation-report.html
```

这个更偏向服务端总览产物。

## 典型使用场景

### 场景 1：手动训练后检查本轮第一名
1. 跑 `trainer.py`
2. 得到 `best-of-batch.json`
3. 对它单独评估
4. 查看 `.eval-report.html`

### 场景 2：批量比较某个档位所有候选
1. 对 `artifacts/models/exports/pc/` 整个目录评估
2. 打开 `evaluation-report.html`
3. 比较 `avgSelectionScore`、`avgScore`、`avgFrames`

### 场景 3：对默认模型做单独复核
直接评估：

```text
data/models/profiles/pc.json
```

---

## 你通常应该重点看什么

### 第一优先级
- `avgSelectionScore`

### 第二优先级
- `avgScore`
- `avgFrames`

### 第三优先级
- `survivalRatio`
- `stallSteps`
- `repeatCellCount`

如果一个模型：
- 苹果数很高
- 但停滞和重复踩格很严重

它的最终选择分未必最好。

---

## 注意事项

1. 评估脚本只负责评估，不会自动把模型晋升为默认模型。
2. 如果你要“设为默认”，建议通过模型管理页操作。
3. 目录评估时，请确认目录里没有混入不该参与比较的无关 JSON。
4. 评估结果最适合作为候选模型排序依据，而不是唯一标准；最好再到浏览器运行测试台看真实运行效果。
