# 长期自动训练说明

## 入口

```bash
python src/train/snake_nn/long_run_trainer.py
```

对应脚本：

```text
src/train/snake_nn/long_run_trainer.py
```

---

## 适合什么场景

长期自动训练适合：

- 长时间后台筛选模型
- 自动恢复未完成 trial
- 自动把弱模型清理掉
- 在候选池足够大时尝试 hybrid 融合
- 尽量减少人工干预

它更像“长期调度器”，不是单轮实验脚本。

---

## 当前长期训练的核心原则

### 1. resume-first

长期训练启动后，不会立刻生成新 seed。

它会先扫描：

```text
artifacts/models/checkpoints/<profile>/*-latest/
```

如果存在：

- 尚未达到试训最后比较代数（`trial_generations - 1`）的 checkpoint
- 或已过试训阶段但尚未达到完整训练最后比较代数（`full_generations - 1`）的 checkpoint
- 且参数兼容当前训练配置

就会优先恢复这些未完成的 backlog checkpoint。

### 2. generation-matched history comparison

长期训练比较新模型和历史模型时，不是直接重评估最终模型，而是比较：

- 指定代数对应的**最终已评估代历史快照**

例如：

- `trial_generations = 300`
- 实际比较代数通常是 `299`

- `full_generations = 1000`
- 实际比较代数通常是 `999`

### 3. backlog 清空后才考虑 hybrid / new seed

调度优先级是：

1. backlog checkpoint
2. hybrid
3. new seed

---

## 核心阶段

### 1. resume backlog 模式

如果目录中存在未完成试训的 checkpoint：

- 优先恢复它们
- 先把中断的 trial 补完
- 不直接创建新 seed

### 2. warmup 模式

如果当前可比较历史候选数不足：

- 直接完整训练新 seed
- 优先把候选池堆起来

### 3. trial 模式

如果候选池规模已经够大：

- 先把新 seed 跑到 `trial_generations`
- 再拿 trial 历史快照去比较

### 4. full train 模式

trial 通过后：

- 从 trial checkpoint 继续训练
- 跑到 `full_generations`
- 再进入 full 阶段候选池重排

### 5. hybrid 模式

如果：

- backlog 已清空
- 候选池足够大
- 开启了 hybrid
- 并且自上次 hybrid 之后，新增普通 seed 的数量达到阈值

就会：

- 从 top seed 中读取整个人口
- 按分段配额取样
- 合并成新的 hybrid population
- 再继续训练

这意味着当前系统不会在第一次 hybrid 成功后每次都继续优先 hybrid，而是会先重新积累一批新的 seed，再允许下一次融合。

## 主要配置

### 调度层配置

- `profile_id`
- `trial_generations`
- `full_generations`
- `warmup_seed_count`
- `keep_top_n`
- `cleanup_interval_runs`
- `dry_run`

### 训练层配置

- `num_parents`
- `num_offspring`
- `boards_per_individual`
- `episodes_per_board`
- `starvation_scale`
- `score_weight`
- `survival_weight`
- `raw_fitness_weight`
- `raw_fitness_cap`
- `zero_score_penalty`
- `approach_apple_weight`
- `repeat_cell_penalty`
- `stall_penalty`
- `population_checkpoint_interval`
- `resume_strict`
- `parallel_evaluation_enabled`
- `parallel_evaluation_workers`

### hybrid 配置

- `hybrid_enabled`
- `hybrid_min_seed_pool`
- `hybrid_top_seed_count`
- `hybrid_population_size`
- `hybrid_segment_boundaries`
- `hybrid_segment_weights`
- `hybrid_skip_incompatible_sources`
- `hybrid_min_new_seeds_since_last`

其中：
- `hybrid_min_new_seeds_since_last` 表示“自上次 hybrid 之后，至少要新增多少个普通 seed，才允许再次 hybrid”
- 这个配置的目的是避免系统一旦进入 hybrid 条件区间后，就长期连续只做 hybrid，而不再探索新的随机 seed

## 从管理页配置长期训练

管理页顶部菜单的 **长期训练** 分区支持：
- 多套参数预设的保存、切换、重命名、删除
- 参数按功能分组折叠显示（基础参数 / 试训门槛 / 评分与惩罚 / Checkpoint / Hybrid 融合）
- 鼠标悬浮在参数上显示功能解释和取值范围
- 参数以“中文名称(英文key)”格式显示
- 点击 **应用并启动长期训练** 后，后端会读取当前激活预设并启动长期训练
- 训练进行中时启动按钮自动禁用
- 可打开长期训练日志摘要

关于管理页的详细说明，请参阅 [03-模型管理页说明](03-模型管理页说明.md)。

## trial 通过条件

trial 阶段会比较：

- 当前试训模型的历史快照
- 默认模型在同代数上的历史快照
- 历史候选池地板模型在同代数上的历史快照

主要门槛包括：

- `trial_min_avg_score`
- `trial_min_avg_frames`
- `trial_min_selection_ratio_vs_default`
- `trial_min_selection_ratio_vs_topn_floor`

如果不通过：

- 回收该 seed 的 checkpoint
- 可选删除导出模型
- 记录拒绝日志

## 关于“每 5 代才记录一次”的解释

### 训练历史

`training-history.json` / `training-report.html` 是：

- **每代写**

### 整群 checkpoint

`<seed>-latest/` 的覆写频率由：

- `population_checkpoint_interval`
  控制

所以：

- 你看到“每 5 代更新一次”
- 通常说的是 checkpoint
- 不是 history

## 推荐使用方式

### 想稳定长期跑

建议：

- `population_checkpoint_interval = 1`
- `resume_strict = True`
- `hybrid_enabled = False` 或先保守开启

### 想扩大探索

可以：

- 降低 trial 门槛
- 增大 `keep_top_n`
- 增大 `cleanup_interval_runs`
- 再逐步开启 hybrid

### 想快速验证流程

可以：

- 减小 `trial_generations`
- 减小 `full_generations`
- 开 `dry_run=True`

---

## 重要注意事项

1. backlog 恢复只会优先恢复**兼容当前训练参数**的 checkpoint。
2. 不兼容的旧 checkpoint 会被跳过并记日志，不再直接把长期训练跑崩。
3. trial / full 比较看的是历史快照，不是直接看目标代数名义值。
4. hybrid 目前只建议在同 profile、同结构、同 settings 的种群间使用。
