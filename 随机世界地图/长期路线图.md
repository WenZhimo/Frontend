# 随机世界地图生成器长期路线图

## 1. 路线图定位

本文记录随机世界地图生成器的长期演进方向，重点服务于 `geology-v2` 之后的地质、水文、气候、生物群系和资源系统衔接。

当前项目的核心原则保持不变：

- 海陆后置：海陆、海岸线和水体解释必须由 `elev >= seaLevel` 及派生连通性得到，不直接绘制大陆或海洋。
- 状态可解释：地形应能由板块、地壳类型、地壳厚度、地壳年龄、抬升、侵蚀、沉积、盆地、海平面等状态解释。
- 诊断先行：高风险系统优先做诊断字段和 debug 图层，再逐步进入高程或渲染结果。
- 质量优先：在视觉真实性、长期稳定性和物理一致性上优先于速度，但避免明显不可扩展的复杂度。

## 2. 当前已完成基础

截至当前阶段，`geology-v2` 已具备以下主要能力：

- 洋壳年龄出生 / 扩张年龄场。
- 洋底高程解释项：`ageSubsidence`、`thicknessBuoyancy`、`sedimentFill`、`ridgeUplift`、`trenchDepression`、`oceanDepthTerms`。
- 裂谷阶段机与海洋连通性。
- 被动大陆边缘、大陆架、陆坡、陆隆、深海平原和沉积楔。
- 转换断层与旧 fracture zone 残影衰减。
- 造山带生命周期。
- 构造轴线自然化。
- 行星起伏预算。
- 全球相对海平面耦合：`seaLevel = baseSeaLevel + geologicSeaLevelOffset`。

这些系统共同构成 geology-v2 的构造-地形-海平面基础。

## 3. 长期优先级

### 3.1 沉积物预算与搬运闭环

优先级：高。

目标：

- 让 `sediment` 从侵蚀、搬运、沉积、压实和容量上限中产生，而不是表现为累积贴图。
- 降低长时程下 `sediment / basin` 的直色带、块状残影和无限填海风险。
- 为后续水文系统提供更可信的盆地、冲积平原、被动边缘和陆架基础。

关键字段：

- `erosionSource`
- `sedimentFlux`
- `sedimentSink`
- `sedimentCapacity`
- `sedimentCompaction`
- `sedimentLoadSubsidence`
- `sedimentBudgetError`

验证重点：

- 山地和高坡度区是主要侵蚀源。
- 被动边缘、陆架、陆隆、前陆盆地、裂谷盆地、闭合盆地候选是主要沉积汇。
- 739 Myr 长时程不出现全图沉积饱和。
- `sedimentBudgetError` 不长期接近 1。

### 3.2 等静力 / 地壳浮力轻量高程校正

优先级：高，但应在沉积预算之后。

目标：

- 将壳厚、密度、洋壳年龄冷却、沉积负载等状态转化为轻量高程校正。
- 让大陆、过渡壳、洋壳的高低关系更自然。
- 避免单纯由噪声或局部 feature 决定大尺度高程。

关键原则：

- 初版应保持弱耦合，避免直接导致陆海比例剧烈漂移。
- 高程校正应进入 `rebuildGeologyElevation` 的可解释项，而不是后处理贴图。
- `sedimentLoadSubsidence` 可先弱影响或只诊断，稳定后再增强。

验证重点：

- 厚陆壳整体偏高。
- 老冷洋壳整体偏低。
- 沉积负载不会无限压低地表。
- `flatWorldRisk` 不升高。

### 3.3 统一拓扑抽象：cylindrical 到 spherical-ready

优先级：高，必须在完整水文 / 气候系统之前规划。

当前地图拓扑更接近圆柱展开：

- x 方向 wrap。
- y 方向不 wrap，通常 clamp 或跳过越界。

长期目标是支持球面邻接规则：

- 左右边缘仍然相连。
- 穿过北极或南极时，纬度反射，经度偏移半个地图宽度。
- 极区不应成为硬边界或人工堆积带。

不建议立刻全局替换所有邻域访问。应先新增统一拓扑 API：

```js
getNeighbor(grid, x, y, dx, dy, topology)
sampleField(grid, field, x, y, topology)
forEachNeighbor(grid, x, y, callback, topology)
wrapCoordinate(grid, x, y, topology)
```

推荐拓扑模式：

```js
Topology = {
  CYLINDRICAL: "cylindrical",
  SPHERICAL: "spherical"
}
```

球面极点穿越规则示意：

```js
function sphericalWrap(x, y, width, height) {
  if (y < 0) {
    y = -y;
    x += width / 2;
  } else if (y >= height) {
    y = height - 1 - (y - height + 1);
    x += width / 2;
  }

  x = ((x % width) + width) % width;
  return { x, y };
}
```

受影响模块：

- 板块移动与平流。
- 边界检测。
- 地形平滑和扩散。
- 沉积搬运。
- 海洋连通性。
- 距离场。
- 坡度和局部起伏。
- 水文流向。
- 气候风带和纬度带。
- debug-render 与 resolution-check。

实施策略：

1. 新增拓扑工具，不改变默认行为。
2. 在诊断工具和小范围 geology-v2 辅助函数中试点。
3. 将高频邻域访问逐步迁移到统一 API。
4. 在水文 / 气候系统开始前，明确默认拓扑是否切换为 spherical。

验证重点：

- x wrap 行为保持稳定。
- y 极区不再是硬边界。
- 极区无异常棋盘、裂缝、沉积堆积或海洋连通错误。
- 同一种子在 cylindrical 与 spherical-ready 模式下差异可解释。

### 3.4 水文系统

状态：MVP 已接入；后续仍需水量、降水和湖泊填洼。

目标：

- 基于 `elev`、`seaLevel`、`externalSeaMask`、`closedBasinId`、`inlandWaterCandidate`、`basin` 和 `sedimentCapacity` 派生河流、湖泊候选、流域与排水路径。
- 区分外海、内陆闭合盆地、临时低地和真实水文湖泊。
- 当前已实现 topology API 驱动的 D8 流向、`flowAccumulation` 汇流、`riverMask / riverStrength` 主河候选、`drainageBasinId / watershedId` 流域编号、`endorheicBasin / endorheicSink` 内流诊断、`lakeCandidate / wetlandCandidate` 候选层。

关键原则：

- 不要把 geology-v2 的 `inlandWaterCandidate` 直接当成完整湖泊。
- 河流应受坡度、降水、盆地和沉积平原影响。
- 水文不应反向破坏地质解释层。
- MVP 使用统一 runoff 占位，不模拟气候降水、蒸发、地下水、湖面高度或真实水量收支。

验证重点：

- 河流流向外海或闭合盆地。
- 大型湖泊需要合理汇水区，不应凭空出现在规则板块边缘。
- 三角洲和冲积平原应与沉积汇相互印证。
- `hydrologyValid` 应为 true，`flowCycleCount` 应为 0 或极低，`riverContinuityScore` 应接近 1，`externalSeaDrainageShare / closedBasinDrainageShare` 应解释当前陆地排水格局。

下一阶段：

- priority-flood 填洼和湖面高度。
- 降水 / 蒸发输入与季节性 runoff。
- 河口三角洲、泛滥平原、湿地和输沙反馈。

### 3.5 气候系统

优先级：中高，应在基础水文和拓扑抽象之后。

目标：

- 引入纬度、海陆分布、海拔、山脉阻挡、洋流简化项和水汽输送。
- 为河流流量、生物群系、冰川和资源系统提供输入。

关键输入：

- `seaLevel`
- `externalSeaMask`
- `mountainHeight`
- `orographicBarrier`
- `coastalSensitivity`
- `continentality`
- `latitude`

注意事项：

- 气候系统开始前应确认球面拓扑策略。
- 冰盖、冰蚀、峡湾、碳酸盐台地和珊瑚礁可延后，避免过早硬编码。

### 3.6 生物群系与生态分区

优先级：中。

目标：

- 基于温度、降水、海拔、距海、土壤 / 沉积、地形坡度生成生物群系。
- 让森林、草原、沙漠、苔原、湿地等分布能由气候和地形解释。

依赖：

- 水文系统。
- 气候系统。
- 沉积 / 土壤候选字段。

### 3.7 资源系统

优先级：中。

目标：

- 基于构造、沉积盆地、造山带、裂谷、被动边缘、火山弧和古地质记忆派生资源分布。

潜在规则：

- 沉积盆地：油气、煤、盐类、地下水。
- 造山带：金属矿、变质带。
- 裂谷与火山活动：稀有金属、地热。
- 被动边缘：油气与厚沉积层。

依赖：

- geology-v2 地质状态稳定。
- sediment budget 稳定。
- 水文 / 气候可选，但部分资源可先行。

## 4. 技术债与长期风险

### 4.1 拓扑技术债

当前大量函数直接使用 `wrapX`、y clamp 或手写邻域访问。长期切换球面拓扑前，需要逐步收敛到统一拓扑 API。

风险：

- 手动替换容易遗漏。
- 极区可能出现新伪影。
- 旧 debug 指标可能默认假设 y 不 wrap。

处理策略：

- 先新增 API 和诊断。
- 再迁移低风险模块。
- 最后迁移高影响模块，如平流、沉积搬运、水文流向。

### 4.2 诊断字段膨胀

geology-v2 已有大量 debug 字段。后续新增字段时应区分：

- 必须持久状态。
- 可派生字段。
- 仅 debug 字段。
- 仅 world 级 scalar diagnostics。

避免将 global scalar 误建成 per-cell field，例如：

- `geologicSeaLevelOffset` 应是 world scalar。
- `youngOceanShare` 应是 world scalar。
- `capacityBalance` 应是 diagnostics scalar。

### 4.3 长时程稳定性

所有新系统都必须关注：

- 200 Myr 中期稳定性。
- 739 Myr 长时程稳定性。
- 256x128 与 512x256 分辨率收敛性。
- 不出现矩形湖、扇形湖、网格、直线旧边界残影、全图沉积饱和或陆海比例失控。

## 5. 推荐近期任务顺序

近期建议按以下顺序推进：

1. 沉积物预算与搬运闭环。
2. 等静力 / 地壳浮力轻量高程校正。
3. 统一拓扑 API 设计与 cylindrical 默认兼容实现。
4. 球面拓扑诊断模式与小范围试点。
5. geology-v2 邻域访问逐步迁移。
6. 水文系统 MVP。
7. 气候系统 MVP。
8. 生物群系与资源系统。

进入下一阶段前的 GPU 化路线单独记录在 `GPU计算渐进式改造计划.md`。原则是先建立 WebGPU capability / fallback / field compare 工具，再迁移 GPU 友好的 dense formula（等静力、高程重建、局部 stencil、渲染着色），暂不把 connected components、闭合盆地编号、水文汇流等图算法作为第一批 GPU 目标。该文档是长期加速路线，不要求下一轮地质质量调参必须先完成 GPU 工程；稳定的地质规则仍可先在 CPU 路径落地。

GPU Phase 0 已落地能力探测、CPU authoritative 后端骨架、字段分组、CPU-vs-CPU 字段比较工具与 GPU perf profile 骨架；当前没有 GPU compute kernel，`interface-check / long-run-check / resolution-check` 仍默认走 CPU。下一步建议进入 Phase 1：只做 GPU render backend 试验，不碰 `stepWorld`、`updateIsostasy` 或 `rebuildGeologyElevation`。

## 7. 路线图维护规则

- 每完成一个 geology-v2 基础系统，应更新本文的已完成基础和近期任务顺序。
- 每引入一个跨系统字段，应明确它是持久状态、派生字段、debug 字段还是 world 级 scalar。
- 每发现新的长期架构问题，应记录在“技术债与长期风险”中。
- 进入水文 / 气候前，必须重新评估球面拓扑迁移状态。

## 8. 已完成：等静力 / 地壳浮力基础层

已落地轻量等静力高程校正：

- 厚陆壳通过 `crustBuoyancy` 获得稳定基础高程。
- 高密度地壳通过 `densitySubsidence` 下沉。
- 洋壳年龄通过 `lithosphereCooling = sqrt(crustAge) * scale` 控制老洋盆加深。
- 沉积同时通过 `sedimentFill` 填平表面，并通过 `sedimentLoadSubsidence` 产生弱负载下沉。
- `isostaticBase / isostaticResidual` 已接入接口、诊断和 debug-render。

后续优先级：

1. 使用本轮 debug 图层继续校准 transitional crust 的浅海 / 低地范围。
2. 将水文阶段建立在 `externalSeaMask / inlandWaterCandidate / relativeElevation` 上，而不是直接读取等静力内部字段。
3. 若 739 Myr 继续出现局部规则残影，优先从 sediment / oldBoundary / transformMemory 耦合排查，而不是调高等静力强度。

## 9. 已完成：统一拓扑 API 基础层

已新增 `src/sim/topology.js`，当前默认 cylindrical：x wrap、y 不 wrap。拓扑层已经覆盖公共 `grid.indexOf / forEachNeighbor4`，并迁移 `externalSeaMask / closedBasinId / inlandWaterCandidate` 的连通组件识别。

phase 2 已扩展无分配邻域 API 与 spherical-ready 诊断：`forEachNeighbor4 / forEachNeighbor8 / forEachNeighborRadius` 作为热路径入口，数组式 `neighbors*` 保留给 debug / 低频工具；新增 `wrapCoord / isValidXY / componentIds / sample / sampleWrapped`，并通过 `tools/topology-check.mjs` 自检小尺寸 cylindrical 默认、x seam、y no-wrap、邻域对称、半径邻域、flood-fill 和 connected components。

已加入诊断：`topologyKind / wrapXEnabled / wrapYEnabled / neighborConsistencyValid / neighbor4SymmetryValid / neighbor8SymmetryValid / distanceWrapValid / floodFillTopologyValid / connectedComponentTopologyValid / seamContinuityRisk / polarBoundaryRisk / topologyManualAccessRisk / topologyMigrationCoverage / topologyResolutionDrift`。

已迁移：海洋连通性、公共 `grid.forEachNeighbor4`、sediment 8 邻域搬运，以及 `interface-check / long-run-check / resolution-check / metrics-summary` 中一批高风险邻接统计。暂缓项包括分辨率重采样、板块中心漂移和部分构造轴线局部扫描，避免一次性改变现有 cylindrical 视觉结果。

后续进入水文 / 气候时，新增的流域、河网、风场、距离场和连通性逻辑必须优先使用 topology API，避免继续把 spherical-ready 难题分散到各模块里。
