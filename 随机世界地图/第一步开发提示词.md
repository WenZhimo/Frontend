## 目标

实现"随机世界地图生成器"第一阶段：**地形成因引擎**。在浏览器中（纯前端、无构建、打开 `index.html` 即可运行）完成一个可交互的原型，通过板块构造的物理过程生成地形，使山脉出现在板块汇聚边界、海岭/裂谷出现在离散边界，而非随机摆放。完成后地形可随时间演化并实时渲染。

## 上下文

- 本仓库根目录已有 `设计与技术方案.md`，是完整设计依据，**必须先通读**，尤其是：★设计定位与核心原则（"零直接放置原则"）、§3 星球与地图表示、§4.1–4.2 地形与板块模型、§A 因果一致性链、§D 修订后的实施重点。
- `prototype/` 下有已验证的基准与因果链脚本：`bench.js`/`bench2.js`（性能与桶排序水文）、`causal5.js`（气候因果链，非本阶段但可参考其网格/PRNG 风格）。可直接复用其中的 `mulberry32` PRNG、网格容器、`x 轴环绕索引`、`3D 球面噪声采样思路。
- 本阶段**只做 §D 的第 1 步（地形成因）**，暂不实现气候、水文、生物群落、资源、撞击、3D——但代码结构要为后续接入留好扩展点。

## 必须满足的设计原则

1. **零直接放置原则**：所有地形特征（山脉、海岭、裂谷、盆地）必须由板块运动的物理过程推导产生，禁止用噪声直接"画出"山脉。基础噪声只用于生成初始的、无显著地形起伏的洋壳/陆壳占位高程，造山/张裂/侵蚀全部由构造过程驱动。
2. **物理因果性**：汇聚边界→俯冲/碰撞造山（最高地形）；离散边界(洋中脊)→新生洋壳、海底隆起；离散边界(陆内)→裂谷下陷；走滑→断层、微扰。侵蚀使高处降低、沉积物填入低地/海洋。
3. **确定性可复现**：给定相同种子与参数，生成完全一致的星球。用户输入的种子是任意字符串（可包含中文、空格、符号等），内部先用稳定字符串哈希转换为 `uint32`，再喂给种子化 PRNG；禁止直接使用 `Math.random()`。
4. **球面闭合**：`x` 方向环绕（经度闭合），`y` 两极为边界。地形噪声用 3D 球面采样避免接缝。

## 技术规格

- **运行环境**：纯浏览器，原生 ES Modules，无打包/无依赖（Three.js 等留到后续阶段，本阶段用 Canvas 2D 渲染）。
- **架构**：主线程负责 UI 与 Canvas 渲染；模拟放 Web Worker，网格用 Typed Array + `postMessage` transferable 零拷贝传递。如时间不足可先单线程跑通，但代码要预留 Worker 接入点。
- **网格表示**：等距圆柱 2D 网格，默认 512×256（可降级到 256×128 预览）。每格字段至少：`elev:Float32`、`plate:Int32`、`pvx/pvy:Float32`（板块速度）、`btype:Int8`（边界类型：0内部/1汇聚/2离散/3走滑）。`x` 索引环绕：`((x % W) + W) % W`。
- **PRNG**：`mulberry32`（已验证）。新增 `hashSeed(seedText:string):uint32`，用确定性 UTF-8/FNV-1a 或等价稳定哈希把任意字符种子映射为 32 位整数；UI 与保存配方保留原始 `seedText`，模拟层使用派生出的 `seedUint32`。
- **算法**（参考 `bench.js` 已验证的实现）：
  - 板块划分：撒 K 个种子点，多源 BFS flood-fill 分配（131k 格约 8ms）。
  - 边界应力：逐格比较邻格板块 id 与相对速度，按边界方向点积判定汇聚/离散/走滑。
  - 高程更新：汇聚→抬升（强度随烈度），离散洋壳→新生洋壳隆起，离散陆内→下陷，走滑→微扰；每步叠加侵蚀（高程指数衰减）+ 沉积（向低处转移）。

## 用户可调参数（本阶段）

种子（任意字符串输入）、初始含水量（设海平面/海陆比）、地壳运动烈度（板块速度与造山强度）、板块数 K、时间步长（年/百年/千年）、模拟分辨率。提供参数面板（HTML 控件即可，无需美化）。

## 交互与渲染

- Canvas 2D 等距圆柱地图：高程着色（海洋蓝→平原绿→山地棕→雪线白），叠加板块边界（按 `btype` 用不同颜色描边）。
- 播放控制：播放/暂停/单步/重置/重新随机种子。
- 实时显示当前步数、星龄、海陆比。
- 性能目标：512×256 单步（板块构造+侵蚀）≤100ms。

## 验收标准（必须达成）

1. 打开 `index.html` 即可运行，无报错、无需安装依赖。
2. 改变任意字符种子→得到不同但同样合理的星球；相同种子字符串+参数→完全一致。数字字符串 `"123"` 与数字 `123` 不区分输入类型，均作为文本 `"123"` 处理。
3. **可验证的因果性**：渲染高程图与板块边界叠加时，目视确认——最高山脉集中在汇聚边界(红色)；离散边界处为新洋壳隆起或裂谷下陷。可额外做一个简单的定量自检（如：汇聚边界格的平均高程显著高于板块内部），并把结果打印到控制台或界面。
4. 调节烈度→造山更剧烈/平缓；调节含水量→海陆比变化；调节板块数→大陆破碎度变化。
5. 代码结构清晰，模块按 `设计与技术方案.md` §10 的 `src/sim/`（prng/noise/grid/world/tectonics/terrain/evolution）拆分，为后续气候/水文模块留接口。

## 约束

- 不实现气候、降水、生物群落、河流、资源、撞击、3D 地球——这些是后续阶段。但 `evolution.js` 的时间步编排要预留这些子步骤的调用位置（先留空函数/注释占位）。
- 不引入任何外部 npm 依赖或构建工具。
- 遵循 `设计与技术方案.md` 的全部约定；如与之冲突，以设计文档为准。
- 完成后简要说明：实现了什么、如何运行、如何验证因果性、为后续阶段留了哪些接口。
