# CLAUDE.md

## 项目概览

世界造山（World Orogen）是一个使用 Three.js 和原生 ES 模块的浏览器端程序化行星生成器，无需构建步骤。

**世界造山是行星概念艺术工具，不是地球物理模拟器。** 所有功能都应优先让输出更可信、更好看，或帮助用户更快迭代。不要为了追求物理精确而明显拖慢生成；如果简单近似能达到同样视觉效果，就使用简单方案。

## 指导原则

1. **艺术吸引力**：输出应有趣、可信并受真实科学启发；审美优先。
2. **易用与效率**：界面应直观，生成应快速，不为真实性牺牲可用性。
3. **科学可信度**：地形、构造和气候要以真实行星科学为基础，但不要求严格物理仿真。

## 用户喜欢的核心优势（必须保护）

1. **气候模拟深度**：风、洋流、降水和柯本气候是最常被提到的差异化能力。
2. **浏览器即时运行、零摩擦**：无需安装、账号或构建。
3. **交互式板块编辑**：Ctrl-click 多选再重建是关键差异点。
4. **真正的球体和正确包裹**：球体优先、等距圆柱地图为辅助视图。
5. **免费开源**：不要加入付费墙、功能门槛或专业版分层。
6. **移动端可用**：保持底部抽屉、触控目标和双指缩放。
7. **地形美感**：保护山脉、侵蚀和海岸线后处理的视觉质量。

## 关键规则

- 任何代码变更后检查 `README.md` 是否需要同步。
- 影响新手引导的变更要更新 `index.html` 的 `#tutorialOverlay`。
- 新增重要用户可见功能时，询问是否更新 `#whatsNewOverlay`。
- UI 变更必须检查移动端触控目标、触摸等价交互、提示位置和弹窗可用性。
- 模拟或气候代码变更必须保证尺度不变性，不要使用未按分辨率换算的 hop 数、邻居位移或固定 pass 数。
- 气候参数应放入 `js/climate-config.js`，并在 `tuning/climate/param-space.mjs` 给出范围。
- 气候行为变化后运行 `node tuning/climate/evaluate.mjs`，必要时再用 `node tuning/climate/optimize.mjs`。
- 功能变化后检查 SEO / AISEO 文件：`index.html` head、JSON-LD、隐藏 `<main>`、`llms.txt` 和 `sitemap.xml`。
- 增删或修改滑块后，必须同步 `js/planet-code.js` 和 `js/main.js` 的滑块映射。
