# 世界生成与文明演化开发总纲

## 1. 核心目标

本项目的终极目标不是单纯生成一张地形图，而是为游戏、架空小说和世界观设计提供一个足够广阔的时空舞台：先生成可信的行星环境，再在适合的时间窗口中观察文明出现、迁徙、分化、兴衰与遗迹沉积。

目标时间尺度分为两层：

- **地质 / 行星尺度**：以百万年为步长观察约 2-10 亿年的板块、造山、海陆、气候和生态变化。
- **文明 / 历史尺度**：以年、十年或世纪为步长，在选定行星快照上观察数千年至数十万年的文明发展。

科学性原则是“可信优先于严格”：每一步应有合理解释和稳定视觉结果，但不要求成为严格地球物理或人类学模拟。

## 2. 主线决策

后续主线调整为：

```text
World Orogen
  = 主要功能底座 / 浏览器端球形行星生成 / 地形 / 气候 / 可视化 / 导出

本地 geology-v2 项目
  = 深时地质演化参考实验室 / 规则库 / 诊断经验

WorldEngine
  = 静态世界生成管线参考 / 气候、生物群系、输出格式参考

ftomassetti/civs
  = 文明历史层参考 / 迁徙、语言、聚落、政体、农业、分裂与灭亡规则参考

GPlates / pyGPlates / GPlately
  = 球面板块运动与深时重建参考 / Euler rotation、plate ID、motion path、flowline、速度场与边界分类代码思路参考
```

因此，后续不再把本地项目继续扩成完整大一统模拟器。更合适的方向是：以 World Orogen 为产品底座，吸收本地 geology-v2 的深时地质经验，参考 GPlates 的球面板块运动与重建代码思路，再参考 civs 建立历史 / 文明层。

## 3. 项目定位

### World Orogen 作为主产品底座

World Orogen 已经具备接近目标产品的外壳：浏览器端运行、球形行星、板块与地形生成、侵蚀、气候、洋流、Koppen 气候、检查图层、导出与交互可视化。它的项目哲学也接近本项目需求：为世界构建提供“可信而快速”的行星概念设计，而不是严格科学仿真。

后续若基于 World Orogen 直接 fork 和分发，需要注意其 GPL-3.0 授权义务。若只是学习思路、重写规则和结构，则仍应避免复制 GPL 代码。

### 本地 geology-v2 作为参考实验室

本地项目保留为 `local-geology-v2-reference/`，定位为“深时地质实验记录”，不再作为主产品扩展方向。它最有价值的经验包括：

- 海陆后置：海陆由统一高程场和海平面切分，而不是先硬编码大陆 / 海洋。
- 洋壳年龄场：洋中脊出生、扩张年龄、年龄沉降解释海底深浅。
- 裂谷阶段机：陆壳减薄 -> 裂谷盆地 -> 过渡壳 -> 新生洋盆候选 -> 连通外海后成为年轻洋盆。
- 海洋连通性：区分外海、内陆低地、闭合盆地和候选水体。
- 旧边界衰减：转换断层和 fracture zone 不应长期留下强直线高程残影。
- 长时程诊断：检查棋盘、直线色带、旧边界阴影、分辨率漂移和渲染/模拟分歧。

### GPlates 作为板块运动代码思路参考

GPlates、pyGPlates 和 GPlately 不适合作为主产品底座，也不应直接替代 World Orogen。它们的价值在于提供真实板块重建工具链中已经验证过的“球面运动表达方式”：板块 ID、有限旋转、Euler pole、rotation model、motion path、flowline、静态板块多边形、重建点线面、速度场查询和相邻板块边界分类。

后续为 World Orogen 添加演化功能时，应重点参考 GPlates 的代码组织思想，而不是直接复制实现：

```js
PlateMotionModel = {
  timeMyr,
  plates,
  plateIdByCell,
  anchorPlateId,
  rotationPoles,
  finiteRotations,
  velocityAtCell(cellId, timeMyr),
  reconstructPoint(point, fromTimeMyr, toTimeMyr),
  reconstructFeature(feature, fromTimeMyr, toTimeMyr),
  classifyBoundary(edgeId, timeMyr)
}
```

工程化原则：

- **板块运动必须是球面旋转**：不要再把板块长期运动抽象为二维平移；每个板块应围绕 Euler pole 产生球面切向速度场。
- **同板块内部速度应一致**：板块内部主要继承同一个旋转模型，边界处由相邻板块相对速度产生构造作用。
- **边界类型由相对速度推导**：divergent / convergent / transform 应尽量由边界两侧速度差、法向分量和切向分量计算，而不是只靠随机标签。
- **构造要素要可重建**：缝合线、旧海岭、热点轨迹、裂谷轴、造山带轴线等应作为可随时间重建或衰减的 feature，而不是一次性贴图。
- **程序化星球仍要保留自由度**：本项目生成的是架空行星，不需要套用真实地球数据；GPlates 只提供运动模型和数据结构启发。

### WorldEngine 作为环境管线参考

WorldEngine 的价值在于传统世界生成流程：板块、侵蚀、雨影、温度、降水、湿度、渗透性、Holdridge 生物群系和多图层输出。它适合参考“地形如何转成气候、生物群系和文明输入”，但不适合作为现代浏览器主底座。

### civs 作为历史层参考

civs 的价值在于文明演化模型：迁徙、语言、部落 / 酋邦 / 国家、聚落创建与毁灭、农业、生活方式转变、群体分裂、增长和灭亡。后续应参考其规则思想，而不是直接移植 Clojure 代码。

## 4. 目标架构

```text
Planet Layer
  spherical mesh / projection / rendering / snapshots

Plate Motion Layer
  plate IDs / Euler poles / finite rotations / spherical velocity fields / reconstructed tectonic features

Geology Layer
  plates / crust / orogeny / rifts / ocean crust age / sediment / sea level

Climate & Ecology Layer
  temperature / precipitation / winds / currents / biomes / habitability

Resource Layer
  minerals / fertile land / harbors / migration corridors / barriers

Civilization Layer
  populations / cultures / languages / settlements / migration / states / collapse

Narrative Layer
  eras / ruins / migration maps / cultural memory / exports for games and fiction
```

核心数据流：

```text
geology state
  -> terrain / sea / coast / mountains / basins
  -> climate and ecology
  -> habitability and mobility fields
  -> civilization emergence and migration
  -> historical snapshots and narrative exports
```

## 5. 文明层输入字段

文明层不应直接读取杂乱的地形实现细节，而应读取稳定的派生字段：

```js
WorldInputsForCivilization = {
  habitability,
  freshwaterAccess,
  agriculturePotential,
  pastoralPotential,
  mobilityCost,
  riverTravel,
  seaTravel,
  resourceAttraction,
  isolation,
  naturalBarrier,
  harborPotential,
  floodplainPotential,
  disasterRisk
}
```

第一版文明状态可以保持极简：

```js
CivilizationState = {
  timeYear,
  populationGroups,
  cultureId,
  languageId,
  settlementRank,
  subsistenceMode,
  migrationPressure,
  technologyLevel,
  tradeReach,
  conflictPressure,
  collapseRisk
}
```

## 6. 推荐开发阶段

### 阶段 0：World Orogen 审计

- 梳理 repo 结构、数据结构、生成 pipeline、UI 状态、渲染层、导出层。
- 确认 GPL-3.0 授权边界。
- 找出时间轴、快照、历史层最适合插入的位置。
- 同时建立 GPlates 参考清单：记录哪些代码思路可借鉴，哪些 GPL 实现不能直接复制。

验收：

- 形成审计文档。
- 标出可改模块、不可复制风险、和需要重写的核心接口。
- 形成 `PlateMotionModel` 初版接口草案，明确 Euler pole、速度场、边界分类、feature reconstruction 的最小字段。

### 阶段 1：时间轴与快照系统

- 增加 `timeMyr` / `timeYear` 分层。
- 增加播放、暂停、步进、快照缓存、前后对比。
- 不急着做完整地质演化，先让“世界状态可随时间保存和观察”。

验收：

- 浏览器中能播放和暂停。
- 能回看快照。
- 控制台无错误。
- 地图、球体、检查图层都能在快照间切换。

### 阶段 2：轻量地质演化

- 从本地 geology-v2 迁移规则思想：洋壳年龄、旧山带衰减、裂谷阶段、旧边界衰减、沉积填充。
- 从 GPlates 迁移代码思路：板块 ID、球面有限旋转、Euler pole、相对速度边界分类、motion path / flowline 式构造轨迹。
- 先做“可信变化”，不追求严格连续板块重建。

验收：

- 2 亿年和 7 亿年样本不出现大面积棋盘、规则扇形海、硬直板块海岸、旧边界强残影。
- 同一种子可重复。
- 多分辨率结果风格收敛。
- 单个板块内部速度场连续，边界构造类型能由相邻板块相对速度解释。
- 长期演化中，跨投影接缝和极区的板块轨迹保持球面连续。

### 阶段 3：环境输入层

- 将地形、气候、生物群系和资源转成文明层输入字段。
- 参考 WorldEngine 的气候 / 生物群系生成管线。

验收：

- 有 habitability、freshwaterAccess、agriculturePotential、mobilityCost 等 debug 图层。
- 文明层不直接依赖底层地形临时变量。

### 阶段 4：文明 MVP

- 参考 civs：从若干人群出现点开始，模拟迁徙、定居、农业化、语言分化、聚落成长和群体分裂。
- 第一版只追求“能观察历史轨迹”，不做复杂战争 AI。

验收：

- 能在地图 / 球体上看到人群迁徙路径。
- 能查看文化、语言、聚落、人口变化。
- 同一种子历史可复现。
- 不同世界环境产生明显不同文明路径。

### 阶段 5：叙事与导出

- 输出时代摘要、迁徙图、文明谱系、语言族群、古遗迹、灾变事件。
- 为游戏和小说提供可直接使用的世界设定材料。

验收：

- 能导出地图、图层和历史摘要。
- 能按时间点查看文明分布。
- 能生成“这个世界为什么变成这样”的解释链。

## 7. 本地项目保留 / 停止原则

保留：

- 规则研究文档。
- geology-v2 核心实验代码。
- 诊断工具、检查脚本、debug-render 思路。
- 真实球面拓扑和 GPU 改造经验。

停止继续投入：

- 把本地项目继续扩成完整产品。
- 在本地项目上继续大规模 UI 打磨。
- 在本地项目中提前实现完整水文、气候、生态和文明系统。
- 为本地项目继续做长期 GPU 重构，除非该经验能直接迁移到 World Orogen 主线。

## 8. 授权与工程边界

- World Orogen：适合作为主底座，但 GPL-3.0 意味着直接 fork 和分发修改版需要遵守 GPL 义务。
- WorldEngine：MIT，适合参考世界生成流程和数据输出思想。
- civs：Apache-2.0，适合参考文明模拟规则。
- GPlates / pyGPlates / GPlately：适合作为球面板块重建、有限旋转、速度场和构造 feature 数据结构参考；若直接复用 GPL 代码，需要遵守相应 GPL 义务。
- 本地 geology-v2：作为自有实验经验与迁移参考。

后续实现时应优先“参考思想、重写实现”，尤其在授权不一致时避免直接复制代码。

## 10. 下一步建议

下一步不应继续在本地 geology-v2 上扩功能，而应做 World Orogen 审计：

1. 拉取 / fork World Orogen。
2. 梳理生成、渲染、气候、检查图层和导出模块。
3. 梳理 GPlates / pyGPlates / GPlately 的板块运动模型，提炼可重写的 `PlateMotionModel` 思路。
4. 写 `World Orogen Evolution Fork 技术审计.md`。
5. 设计 `EvolutionState`、`PlateMotionModel` 与时间轴接口。
6. 先做浏览器内可验证的快照 / 播放 MVP。

这条路线的核心判断是：

> World Orogen 负责看见星球，GPlates 负责启发球面板块如何运动，WorldEngine 负责理解环境，civs 负责让历史动起来，本地 geology-v2 负责提供程序化深时演化经验。
