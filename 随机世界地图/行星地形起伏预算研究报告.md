# 行星地形起伏预算研究报告

访问日期：2026-07-01

## 1. 摘要

- 从行星形成和地质演化角度看，天然类地行星几乎不会拥有完全平滑的表面。撞击、火山、构造变形、地壳厚度/密度差异、等静力响应、侵蚀和沉积都会制造或重分配地形起伏。
- 大量水资源不会把行星自动削成平板。水会侵蚀高地、搬运沉积物、填充盆地，同时也会切割河谷、形成陆架/陆坡/深海平原，并通过海平面切分放大高程分布的视觉意义。
- 对地图生成器来说，“全局地形起伏预算”很有价值：它能防止长时程后世界被侵蚀、沉积和平滑拉成不合理的平板大陆。
- 这个规则应作为 geology-v2 的质量约束和诊断层，而不是直接给 `elev` 加随机噪声。
- 推荐在“构造轴线自然化”之后加入：`planetaryReliefBudget / reliefDeficit / hypsometricSpread / flatLandShare / tectonicReliefSupply / erosionFlatteningPressure`。
- 核心原则仍应保持“海陆后置”：陆海由 `elev >= seaLevel` 派生，起伏预算只调节地质过程的强弱和诊断风险。

## 3. 地质结论：为什么天然含水行星不应是平板

### 3.1 行星表面天然有起伏

行星表面会记录内部和外部过程。LPI 的行星构造资料指出，类地行星早期经历高温状态，冷却后形成岩石圈，内部热运动继续使表面变形。CUNY Pressbooks 的行星地质教材也强调，行星表面都存在高点和低点，地形包括山、谷、坑、峡谷等。

工程含义：

```js
planetaryReliefSupply =
  impactReliefMemory
  + volcanicRelief
  + tectonicRelief
  + crustalBuoyancyRelief
  + dynamicTopography;
```

即使项目暂不做撞击坑和热点，仍应保留“行星级基础起伏来源”的预算概念。

### 3.2 地球的高程分布不是单峰平板

NOAA ETOPO 是全球地形与海底地形数据模型；SERC 的 hypsometric curve 教材说明，地球高程曲线常用来展示海洋地壳与大陆地壳造成的两个主要高程域。NASA “Draining the Oceans” 可视化也展示了海底并非平坦，海平面下降时会显露大陆架、洋中脊等结构。

工程含义：

```js
hypsometricSpread = percentile(elev, 0.95) - percentile(elev, 0.05);
landReliefSpread = percentile(elev where land, 0.9) - percentile(elev where land, 0.1);
oceanReliefSpread = percentile(elev where sea, 0.9) - percentile(elev where sea, 0.1);
```

这些指标应长期保持在合理范围，不应在数亿年后塌缩到接近 0。

### 3.3 等静力和地壳浮力会制造长期高差

LibreTexts 和 SERC 都强调，陆壳与洋壳厚度、密度不同；岩石圈会因负载、厚度和密度变化而产生等静力响应。洋壳通常更薄更密，陆壳通常更厚更轻，因此天然会分化出不同高程域。

工程含义：

```js
isostaticRelief =
  crustThickness * thicknessWeight
  - crustDensity * densityWeight
  - lithosphereCooling * ageWeight;
```

当前项目已经有 `crustThickness / crustDensity / crustAge / ageSubsidence / thicknessBuoyancy`，下一步可把它们纳入全局起伏预算诊断，而不是只作为局部高程项。

### 3.4 水会削平，也会切割和重分配地形

Pelletier 的地貌演化章节指出，地貌响应构造抬升、基岩风化、流水/风/冰等介质的沉积物搬运。Burbank & Pinter 讨论了构造与地表过程相互作用：构造制造坡度和高差，地表过程侵蚀并搬运物质。

工程含义：

水文前可以先用简化项：

```js
erosionFlatteningPressure =
  sedimentTransportPotential
  + basinFill
  + slopeDiffusion
  + oldOrogenyErosion;

reliefDeficit = targetReliefBudget - measuredRelief;
```

如果侵蚀/沉积让世界过平，不应直接加噪声，而应略微提高构造抬升、保留旧地形记忆，或降低过度平滑。

## 4. 对当前地图生成器的价值

### 4.1 防止长时程平板世界

当前 geology-v2 已经有许多“平滑”机制：侵蚀、沉积、被动边缘、深海平原、旧边界衰减。这些机制各自合理，但叠加后可能把高程方差压得过低。

建议新增风险指标：

```js
globalElevationStd
landElevationStd
oceanElevationStd
hypsometricSpread
flatLandShare
largePlainShare
reliefDeficit
```

### 4.2 稳定海陆后置

如果全图过平，`seaLevel` 的微小变化就会导致大面积陆海翻转。合理起伏可以让海盆、陆架、内陆盆地和大陆高地更稳定。

建议指标：

```js
seaLevelSensitivity =
  share(abs(elev - seaLevel) < smallBand);

coastInstabilityRisk =
  seaLevelSensitivity * (1 - hypsometricSpread);
```

### 4.3 给水文/气候预留真实梯度

河流、湖泊、流域、雨影都需要高程梯度。若大陆整体太平，后续水文只能依赖随机噪声或人工规则，违背 geology-v2 的可解释原则。

建议指标：

```js
drainageGradientPotential = averageSlopeOnLand * landReliefSpread;
orographicReliefPotential = percentile(orographicBarrier, 0.95);
```

## 5. 推荐工程规则

### 5.1 新增“行星地形起伏预算”诊断层

新增 derived/diagnostic 字段：

```js
planetaryRelief
tectonicReliefSupply
isostaticReliefSupply
volcanicReliefSupply
erosionFlatteningPressure
sedimentSmoothingPressure
reliefDeficit
hypsometricSpread
flatLandShare
largePlainShare
seaLevelSensitivity
```

这些字段默认只诊断，不直接覆盖 `elev`。

### 5.2 预算公式

建议初始近似：

```js
tectonicReliefSupply =
  activeOrogeny * 1.0
  + oldOrogeny * 0.35
  + ridge * 0.45
  + rift * 0.25
  + trench * 0.25
  + islandArc * 0.35;

isostaticReliefSupply =
  abs(thicknessBuoyancy)
  + abs(ageSubsidence)
  + abs(oceanDepthTerms);

erosionFlatteningPressure =
  sediment * 0.35
  + basin * 0.25
  + abyssalPlain * 0.35
  + sedimentWedge * 0.2;

planetaryReliefBudget =
  tectonicReliefSupply
  + isostaticReliefSupply
  + volcanicReliefSupply
  - erosionFlatteningPressure;
```

### 5.3 不直接加随机噪声

错误做法：

```js
if (worldTooFlat) elev += randomNoise * amount;
```

推荐做法：

```js
if (reliefDeficit > threshold) {
  preserveOldReliefMemory();
  reduceOverSmoothingSlightly();
  boostTectonicReliefSourcesSlightly();
  retainCratonAndBasinContrast();
}
```

也就是说，起伏预算应调节已有地质过程，而不是绕过地质解释层。

### 5.4 局部平原允许存在

真实行星可以有大平原、陆架、深海平原、沉积盆地。问题不是“不能平”，而是“不能整个行星都缺少高差”。

规则：

```js
largePlainShare = share(land && slope < lowSlope && localRelief < lowRelief);

flatWorldRisk =
  globalElevationStd < minGlobalStd
  && hypsometricSpread < minSpread
  && largePlainShare > maxPlainShare;
```

若 `largePlainShare` 高但 `hypsometricSpread` 正常，则说明只是有广阔平原，不必惩罚。

## 6. 推荐加入顺序

建议排在当前“构造轴线自然化”之后：

1. 构造轴线自然化：先让山脉、海岭、海沟、裂谷的位置更自然。
2. 行星地形起伏预算：再做全局质量约束，避免长时程平板化。
3. 沉积预算与水文前置：把侵蚀物进一步交给河流/盆地/陆缘系统。

原因：

- 如果轴线仍过直，起伏预算可能放大直线山脉。
- 先自然化轴线，再维持全球高差，视觉和地质解释都会更稳。

## 8. 验收标准

- 739 Myr 后不应出现全球平板大陆。
- 局部可有广阔平原，但 `hypsometricSpread / landReliefSpread` 不能塌缩。
- `seaLevelSensitivity` 不应长期过高，否则海陆后置会变得不稳定。
- 起伏不足时，系统应调节构造抬升、旧地形记忆和平滑强度，而不是随机加噪声。
- 新指标不能破坏 legacy。
- 不应导致陆海比大幅漂移。

## 9. 需要暂缓的内容

以下内容与行星起伏有关，但建议暂缓：

- 完整撞击坑系统：会影响起伏，但需要单独的年龄、侵蚀和覆盖逻辑。
- 热点/超级火山链：可作为后续海山/高原来源。
- 冰川地貌：依赖气候。
- 真实河网侵蚀：应进入 hydrology 阶段。
- 生物礁/碳酸盐台地：依赖气候与生物圈。

## 10. 结论

“天然含水类地行星应具有明显全球地形起伏”适合加入当前项目，但应作为 geology-v2 的全局诊断与质量约束，而不是直接的随机扰动。它能增强海陆后置的稳定性，防止长时程平板化，并为后续水文、气候、生物圈提供真实地形梯度。推荐在“构造轴线自然化”之后实现。

## 11. 与地质海平面耦合的衔接

行星起伏预算与地质海平面耦合是同一套海陆后置框架的两侧：起伏预算解释 `elev` 的全局高差是否足够，地质海平面耦合解释同一个 `elev` 场下洋盆容量变化如何改变最终 `seaLevel`。

当前实现采用：

```js
seaLevel = baseSeaLevel + geologicSeaLevelOffset;
```

其中 `baseSeaLevel` 来自基础 waterLevel / 总水量切线，`geologicSeaLevelOffset` 是全球洋盆容量平衡得到的单一标量。它不是逐格海平面，也不应产生 `geologicSeaLevelOffsetField`。最终海陆仍由 `elev >= seaLevel` 派生。

与起伏预算的关系：

- `ridgeVolumeSignal / isYoungOcean` 表示年轻、热、浅的洋壳占比和洋中脊体积，倾向减少洋盆容量并推高相对海平面。
- `oldOceanCapacitySignal` 表示老洋壳冷却沉降和深洋盆容量，倾向压低相对海平面。
- `sedimentDisplacementSignal` 表示沉积楔、陆隆、陆架和盆地填充造成的局部填浅，弱正向推高相对海平面。
- `trenchCapacitySignal` 表示海沟深水容量，弱负向压低相对海平面。
- `coastalSensitivity` 与 `seaLevelSensitivity` 相近，但更偏静态地貌敏感性：近海平面、低坡度、低局部起伏、陆架、被动陆缘和盆地会更敏感。

诊断建议：

```js
capacityBalance =
  ridgeVolumeNormalized * ridgeWeight
  + youngOceanNormalized * youngWeight
  + sedimentDisplacementNormalized * sedimentWeight
  - oldOceanCapacityNormalized * oldWeight
  - trenchCapacityNormalized * trenchWeight;

targetGeologicSeaLevelOffset =
  clamp(capacityBalance * maxOffset * couplingStrength, -maxOffset, maxOffset);
```

验收时应同时检查：

- `geologicSeaLevelOffset` 有合理变化，但不长期卡在 `maxOffset`。
- `abs(geologicSeaLevelLandShareDelta)` 小且可解释。
- `coastalFlipRisk` 不显著偏高。
- `hypsometricSpread / landReliefSpread / globalElevationStd` 不因海平面耦合而塌缩。
- `capacityBalance` 为正时 target offset 倾向为正，为负时倾向为负。

剩余风险：地质海平面耦合目前只是小幅、缓慢、限幅的全球标量，不包含气候、冰量、真实水文补给、风暴潮或局部湖面高度。未来若加入 climate/ice offset，应与 `geologicSeaLevelOffset` 在全局层组合，而不是改变“每个 cell 共享同一个最终 seaLevel”的约束。
