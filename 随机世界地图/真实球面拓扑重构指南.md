# 真实球面拓扑重构指南

## 1. 目标与边界

本指南用于后续以“目标模式”引用，指导项目从当前的二维圆柱展开拓扑，重构为：

- 真实球面拓扑上的模拟核心。
- 可切换投影的渲染层。
- 可验证、可回退、可渐进迁移的工程体系。

当前项目的地图并不是严格球面模拟。现有实现主要是：

- `width * height` 的二维矩形数组。
- `x` 方向 wrap，`y` 方向不 wrap。
- 局部使用 `spherePointForCell()` 做球面坐标辅助。
- 许多模块仍直接使用 `wrapX(width, x)`、`y * width + x`、矩形邻居、矩形距离和逐行采样。

本次重构的最终状态不是“在上下边界加一个极点穿越补丁”，而是将模拟世界本身改为球面 cell graph。二维地图只作为投影显示结果存在。

## 2. 核心原则

### 2.1 验证先行

所有迁移阶段必须先有诊断工具和验收指标，再改主模拟逻辑。

禁止做法：

- 先大规模替换邻居逻辑，再肉眼看图判断。
- 只修渲染投影，不修模拟拓扑。
- 新旧拓扑混用但无诊断标记。
- 让 geology-v2 在一部分模块里是球面，在另一部分模块里仍用矩形直接索引。

推荐做法：

- 新增 spherical/cubed-sphere 模式，与 cylindrical 并存。
- 每一阶段都可通过工具命令验证。
- 保留 legacy/cylindrical 作为回归参照，直到球面模式长期稳定。

### 2.2 模拟核心与投影渲染解耦

模拟核心只关心球面 cell：

```js
cellId
position3
lon
lat
area
neighbors
edgeLength
edgeTangent
```
渲染层负责把球面字段投影到二维画布：

```js
renderProjection(world, {
  projection: "equirectangular" | "orthographic" | "mollweide" | "debug-face",
  width,
  height,
});
```

### 2.3 所有全局统计必须面积加权

真实球面拓扑下，统计不应再使用简单 cell count。所有 share/mean/budget 指标应使用：

```js
weightedMean = sum(value[i] * area[i]) / sum(area[i]);
weightedShare = sum(mask[i] * area[i]) / sum(area[i]);
```

涉及：

- `landRatio`
- `seaRatio`
- `youngOceanShare`
- `oldOceanShare`
- `ridge/trench/rift coverage`
- `sedimentMass`
- `erosion/deposition budget`
- `externalSeaShare`
- `closedBasinDrainageShare`
- `resolution-check`

### 2.4 字段可以保持 TypedArray，但索引语义必须改变

`elev`、`crustType`、`sediment`、`btype` 等字段仍应保持一维 TypedArray，便于性能和工具链延续。

但在球面模式下，`id` 不再等价于：

```js
y * width + x
```

而是由球面网格管理：

```js
id = cellId(face, u, v);
```

所有邻接、距离、采样、连通性必须通过 topology/grid API 访问。

## 3. 推荐目标网格：Cubed Sphere

### 3.1 为什么选择 Cubed Sphere

推荐使用 cubed sphere 作为第一代真实球面拓扑。

优点：

- 没有经纬网极点奇异。
- 每个面仍接近二维栅格，便于迁移现有算法。
- 比 icosphere 更容易做 face/local 坐标、debug 图和 GPU 纹理布局。
- 比经纬网极点补丁更彻底，后续不会继续积累极区特殊逻辑。
- 可自然支持可切换投影渲染。

缺点：

- 六个面边界可能成为新的 artifact 来源。
- 面与面之间的方向、邻接、插值需要非常严格。
- 需要新增 face seam 诊断。

### 3.2 暂不推荐的方案

#### 经纬网 + 极点穿越补丁

可以作为临时修复，但不适合作为最终目标。

问题：

- 极点附近面积畸变仍然存在。
- 扩散、沉积、距离场仍受纬度强烈影响。
- 许多算法会继续依赖 `x/y/wrapX`。

#### Icosphere

几何更均匀，但工程成本更高。

问题：

- 旧的栅格算法迁移难度更大。
- 插值、投影采样、GPU 数据布局更复杂。
- 调试工具更难直观看懂。

## 4. 目标数据结构

### 4.1 新增模块建议

```text
src/sim/sphere/vector.js
src/sim/sphere/cubedSphere.js
src/sim/sphere/sphericalGrid.js
src/sim/sphere/sphericalTopology.js
src/sim/sphere/projection.js
src/sim/sphere/spatialIndex.js
```

### 4.2 SphericalGrid 接口

建议结构：

```js
export function createSphericalGrid(options) {
  return {
    topologyKind: "cubed-sphere",
    faceSize,
    faceCount: 6,
    size,
    cells,
    positionX,
    positionY,
    positionZ,
    lon,
    lat,
    area,
    face,
    faceU,
    faceV,
    neighbors,
    neighborStart,
    neighborCount,
    edgeLength,
    edgeTangentX,
    edgeTangentY,
    edgeTangentZ,
    projectionHints,
  };
}
```

TypedArray 版本优先，避免大量对象：

```js
positionX: Float32Array
positionY: Float32Array
positionZ: Float32Array
lon: Float32Array
lat: Float32Array
area: Float32Array
face: Uint8Array
faceU: Uint16Array
faceV: Uint16Array
neighborStart: Int32Array
neighborCount: Uint8Array
neighbors: Int32Array
edgeLength: Float32Array
```

### 4.3 Topology API

所有模拟模块应逐步只依赖这些 API：

```js
topology.forEachCell((id) => {});
topology.forEachNeighbor(id, (nid, edge) => {});
topology.forEachNeighborRing(id, radius, visit);
topology.distance(idA, idB);
topology.connectedComponents(mask);
topology.floodFill(seedIds, passable);
topology.shortestDistanceSeeds(seedIds, options);
topology.sampleFieldAtLonLat(field, lon, lat);
topology.projectCell(id, projection);
```

### 4.4 兼容旧模式

`createGrid(width, height)` 不应立刻删除。建议新增：

```js
createSimulationGrid({
  topologyMode: "cylindrical" | "cubed-sphere",
  resolution: "512x256",
});
```

并让旧 grid 与新 spherical grid 共享尽可能多的字段名。

## 6. 第一阶段：搭建 Cubed Sphere，但不接主模拟

### 6.1 实现内容

新增 cubed sphere 生成：

```js
createCubedSphereGrid(faceSize)
```

每个面局部坐标：

```js
u = (i + 0.5) / faceSize * 2 - 1;
v = (j + 0.5) / faceSize * 2 - 1;
```

将六个面投到立方体，再归一化到球面：

```js
position = normalize(faceVector(face, u, v));
```

### 6.2 必须处理

- face 内邻接。
- face 边界跨面邻接。
- 角点附近邻接。
- area 估算。
- lon/lat 派生。
- cell id 与 face/u/v 互转。

### 6.3 验证门禁

必须通过：

## 7. 第二阶段：加入 spherical experimental world

### 7.1 参数设计

新增参数：

```js
topologyMode: "cylindrical" | "cubed-sphere"
projectionMode: "equirectangular" | "orthographic" | "debug-face"
faceSize: number
```

映射建议：

```text
256x128  -> faceSize 64 或 74
512x256  -> faceSize 96 或 128
1024x512 -> faceSize 192 或 256
```

注意：cubed sphere cell 数为 `6 * faceSize * faceSize`，与矩形 `width * height` 不完全相等。不要强行追求相同 cell 数，优先追求视觉和统计收敛。

### 7.2 createWorld 分支

建议：

```js
if (params.topologyMode === "cubed-sphere") {
  grid = createSphericalSimulationGrid(params);
} else {
  grid = createCylindricalSimulationGrid(params);
}
```

### 7.3 兼容要求

- legacy/cylindrical 不破坏。
- geology-v2 默认仍可在 cylindrical 上运行。
- spherical 模式初期可只跑最小板块和基础渲染，不要求一次接入所有 geology-v2 字段。

## 8. 第三阶段：球面板块系统

### 8.1 板块中心

旧模式：

```js
centersX
centersY
vx
vy
```

球面模式：

```js
plateCenterX/Y/Z
angularVelocityX/Y/Z
```

### 8.2 板块运动

板块漂移应使用球面旋转：

```js
center = rotateAroundAxis(center, axis, angularSpeed * dt);
```

cell 上的板块速度：

```js
velocity = cross(angularVelocity, cellPosition);
```

### 8.3 板块分配

基础版本可用球面最近中心：

```js
distance = acos(dot(cellPosition, plateCenter));
```

后续再加入 weakness/cost field：

```js
cost = sphericalDistance + weaknessPenalty + crustContrastPenalty;
```

### 8.4 边界检测

边界不再从矩形四邻/八邻硬算，而是：

```js
for each neighbor:
  if plate[id] !== plate[nid]:
    classifyBoundary(id, nid)
```

相对速度：

```js
relativeVelocity = velocity[nid] - velocity[id];
boundaryNormal = tangentNormalBetweenCells(id, nid);
normalComponent = dot(relativeVelocity, boundaryNormal);
shearComponent = length(relativeVelocity - normalComponent * boundaryNormal);
```

分类：

```js
if (normalComponent < -threshold) convergent
if (normalComponent > threshold) divergent
if (shearComponent dominates) transform
```

### 8.5 验证门禁

新增：

```powershell
node .\tools\plate-pole-crossing-check.mjs '龙骨海-纪元7' cubed-sphere 64
node .\tools\interface-check.mjs '龙骨海-纪元7' 0 geology-v2 256x128 --topology cubed-sphere
```

验收：

- 板块可跨任意投影边缘连续移动。
- 极区不再被截断。
- equirectangular 投影中，穿极线条从同侧半图偏移处回归。
- `boundaryKind` 在 face 边界上连续。

## 9. 第四阶段：连通性、距离场与洪泛迁移

优先迁移：

- `connectedComponents`
- `floodFill`
- `distanceToOcean`
- `coastDistance`
- `externalSeaMask`
- `closedBasinId`
- `inlandWaterCandidate`

全部基于 topology graph：

```js
const components = topology.connectedComponents(mask);
const flood = topology.floodFill(seedIds, passable);
```

### 9.1 外海定义

球面上没有“地图左右边缘外海”。外海应由最大连通海域或显式 global ocean component 定义：

```js
externalSea = largestConnectedSeaComponent(seaMask);
```

可选规则：

- 最大海域为 external sea。
- 若多个大海域接近，可保留多外海 component。
- 闭合盆地仍以不连通 external sea 且低于海平面定义。

### 9.2 验证指标

```js
externalSeaShareWeighted
closedBasinCount
closedBasinAreaWeighted
floodFillTopologyValid
connectedComponentTopologyValid
faceBoundaryFloodContinuity
```

## 10. 第五阶段：噪声与初始场球面化

所有核心地质噪声应从 2D 噪声迁移到 3D 球面噪声。

推荐：

```js
noise3(position.x, position.y, position.z, seed)
fbm3(position, octaves, lacunarity, gain)
domainWarpSphere(position, seed)
```

适用字段：

- `baseElev`
- `crustReference`
- `weakness`
- `geologyBroadNoise`
- `geologyMicroNoise`
- `mountainAxisSeed`
- `sedimentCapacity` 的软化噪声

验收：

- 左右接缝无断裂。
- face seam 无硬线。
- 极区无放射纹理。
- 同一种子在不同投影下结构一致。

## 11. 第六阶段：地质过程迁移

### 11.1 必须替换的旧模式

重点搜索并消除 spherical 模式下的这些直接用法：

```js
wrapX(width, x)
y * width + x
for (let y = 0; y < height; y++)
for (let x = 0; x < width; x++)
field[y * width + wrapX(width, x + dx)]
```

替代：

```js
for (let id = 0; id < grid.size; id += 1)
topology.forEachNeighbor(id, ...)
sampleNeighborRing(grid, id, radius, ...)
```

### 11.2 迁移顺序

推荐顺序：

1. crust initialization
2. boundaryInfluence / boundaryDistance
3. ridge/trench/rift feature generation
4. crustAge birth/expansion field
5. isostasy/elevation rebuild
6. sediment transport
7. basin smoothing
8. passive margin / shelf / slope / rise
9. transform/fracture memory
10. orogeny lifecycle

### 11.3 沉积和扩散

graph flux 形式：

```js
for each cell id:
  for each neighbor nid:
    slope = (field[id] - field[nid]) / edgeLength;
    flux = transportCoeff * slope * edgeConductance * area[id];
```

必须检查：

```js
massBefore
massAfter
massDelta
massConservationErrorWeighted
faceEdgeFluxBalance
```

## 12. 第七阶段：水文前置接口适配

水文暂不必完整球面河流系统，但接口字段必须基于球面拓扑可解释。

必须迁移：

- `externalSeaMask`
- `oceanConnectivity`
- `closedBasinId`
- `depressionMask`
- `distanceToOcean`
- `coastDistance`

暂缓：

- 完整 river routing。
- 高精度湖泊体积。
- 气候驱动降水。

若需要最小水文，可用 topology graph 的最陡下降邻居：

```js
flowTarget[id] = neighbor with lowest hydroElevation;
```

## 13. 第八阶段：投影渲染层

### 13.1 渲染 API

新增：

```js
createProjectionRenderer(canvas, {
  projectionMode,
  outputWidth,
  outputHeight,
  renderBackend,
});
```

不要让 renderer 假设字段天然是二维纹理。

### 13.2 Equirectangular 渲染

每个输出像素：

```js
lon = x / width * 2 * PI;
lat = y / height * PI - PI / 2;
position = lonLatToVec3(lon, lat);
cell = spatialIndex.nearest(position);
color = shadeCell(world, cell);
```

### 13.3 Orthographic 渲染

用于真实球面视觉检查：

```js
projectionMode = "orthographic";
cameraLon
cameraLat
zoom
```

必须能旋转球体，检查：

- face seam。
- 极区连续性。
- 板块穿越边缘。
- 海岸线是否只在投影中断，不在模拟中断。

### 13.4 Debug 投影

必须提供：

- `debug-face`
- `debug-cell-id`
- `debug-neighbor-count`
- `debug-area`
- `debug-face-seam-risk`
- `debug-projection-sampling`

## 14. 第九阶段：GPU 路线

球面拓扑不应被 GPU 工作阻塞。

短期：

- CPU projection renderer 先可用。
- WebGL2 只作为显示后端。

中期：

- 上传 projected image texture。
- 或上传 field + spatial lookup texture。

长期：

- WebGPU compute 才考虑迁移地质过程。
- GPU kernels 必须以 CPU topology 结果为权威验证。

## 17. 完整迁移验收标准

### 17.1 拓扑验收

- `topologyKind === "cubed-sphere"`。
- `neighborSymmetryValid === true`。
- `globalConnectivityValid === true`。
- `areaTotalError` 接近 0。
- `poleSingularityRisk === 0`。
- `faceBoundaryContinuityRisk` 低于阈值。

### 17.2 地质验收

- 板块边界能跨任意投影边缘连续演化。
- 穿越极区的边界不会被截断。
- 海岭、海沟、裂谷不会沿 cubed face seam 硬对齐。
- 200 Myr / 739 Myr 长跑无投影边界残影。
- geology-v2 的海陆后置原则仍成立。

### 17.3 统计验收

- `landRatio` / `seaRatio` 使用面积权重。
- sediment budget 使用面积权重。
- resolution-check 在球面模式下收敛。
- 不同 projection 下统计结果一致。

### 17.4 渲染验收

- equirectangular 图左右接缝连续。
- 极区线条在同侧半图偏移处回归。
- orthographic globe 中同一结构连续。
- debug-face 图能显示 face seam，但地质字段不应沿 seam 出现异常线。

12. `chore: make cubed-sphere topology selectable in UI`

每个提交都必须：

- 保持 `index.html` 可直接打开。
- 通过 `node --check`。
- 有对应工具验证输出。

## 19. 常见失败症状与排查

### 19.1 面边界硬线

可能原因：

- 跨 face 邻接方向错误。
- 噪声仍使用 face-local 2D 坐标。
- 平滑/扩散没有跨 face。

检查：

```powershell
node .\tools\face-seam-check.mjs 128
```

### 19.2 极区结构截断

可能原因：

- 仍在使用 equirectangular `y` 边界。
- 渲染投影中断被误认为模拟中断。
- 某个模块仍使用 `y * width + x`。

检查：

```powershell
node .\tools\plate-pole-crossing-check.mjs '龙骨海-纪元7' cubed-sphere 128
```

### 19.3 海洋连通性异常

可能原因：

- 仍把地图边缘作为外海。
- `externalSeaMask` 没有改成最大连通海域。
- flood fill 没有用 topology graph。

检查：

```js
externalSeaShareWeighted
closedBasinCount
floodFillTopologyValid
```

### 19.4 分辨率检查恶化

可能原因：

- faceSize 与旧 resolution 映射不稳定。
- 统计没有面积加权。
- 噪声频率没有按球面尺度归一化。

检查：

```powershell
node .\tools\resolution-check.mjs '龙骨海-纪元7' 200 geology-v2 --topology cubed-sphere
```

### 19.5 球面图看起来像六面体

可能原因：

- cubed face 坐标直接进入噪声。
- face seam smoothing 不连续。
- projection nearest sampling 太粗。

修复：

- 改用 3D sphere noise。
- 跨 face graph diffusion。
- projection renderer 使用 spatial index + 局部插值。

## 20. 最终切换默认拓扑的条件

只有满足以下条件，才可以考虑把默认拓扑从 cylindrical 改为 cubed-sphere：

- `interface-check` 在 cylindrical 和 cubed-sphere 都有效。
- `long-run-check 200/739 Myr` 在 cubed-sphere 通过。
- `resolution-check` 在 cubed-sphere 收敛。
- `artifact-scan` 没有新增 face seam 风险。
- `debug-render` 能输出 topology/projection/face seam 图层。
- `index.html` 直接打开仍正常。
- CPU Canvas 默认渲染路径正常。
- WebGL2/GPU 路径不是球面迁移的必要依赖。

## 21. 结论

彻底球面化的关键不是“让矩形地图上下边缘接起来”，而是：

1. 先建立可验证的球面 cell graph。
2. 再把板块、距离、连通性、扩散、沉积、水文候选逐步迁移到 graph API。
3. 最后把二维地图变成投影渲染结果。

在这个目标架构下，地图可以继续以矩形方式显示，但模拟本身不再生活在矩形里。这样才能真正解决极区截断、面积偏置、上下边缘不连续、投影边界残影等根本问题。

## 22. 生产网格适配器边界

`src/sim/sphere/productionGridAdapter.js` 现在已经是 `topologyMode: "cubed-sphere"` 下的权威生产网格。旧的 `sphericalWorld` 只保留为显式 `diagnostic-sidecar`，用于历史球面探针和迁移检查；生产 geology-v2 状态必须以 `world.grid` 为准。

### 22.1 适配器原则

- `cubed-sphere-production-grid-adapter` 只暴露 `size / cellCount / faceSize / area / neighbor graph / typed fields`。
- 默认不暴露 `width / height`，避免新代码继续依赖 `y * width + x`。
- 所有生产迁移模块必须以 cell id 遍历，并通过 `topology.forEachNeighbor(...)`、`topology.shortestDistanceSeeds(...)`、`topology.connectedComponents(...)` 访问邻接和距离。
- 如果某个旧模块仍需要 `grid.width / grid.height`，说明它还没有完成球面迁移，不应接入该 adapter。

### 22.2 验证门禁

新增检查：

```powershell
node .\tools\spherical-production-adapter-check.mjs 64
```

它验证：

- `topologyKind === "cubed-sphere"`。
- `size === 6 * faceSize * faceSize`。
- 面积总和接近 `4 * Math.PI`。
- graph 邻接对称。
- typed fields 长度全部等于 cell count。
- adapter 默认没有 legacy `width / height`。

### 22.3 下一阶段迁移边界

生产 geology-v2 模块迁移顺序应从只依赖 cell id 的模块开始：

1. 面积加权统计和只读诊断。
2. 连通性、闭合盆地、外海识别。
3. 距离场和局部平滑。
4. 板块分配、边界分类、速度场。
5. 沉积、侵蚀、地壳年龄、等静力等会改写状态的核心模块。

当前阶段已经越过“只读诊断 sidecar”门槛：`cubed-sphere-production-grid-adapter` 是 cubed-sphere 模式的默认生产网格。后续迁移重点不再是“是否接入 adapter”，而是继续清除具体模块中的矩形索引假设，并保证所有生产读写都通过 graph-backed `world.grid` 完成。

### 22.4 诊断 sidecar 契约

`world.sphericalWorld` 仅允许作为非权威诊断 sidecar 存在：

- `kind === "spherical-experimental-world"`。
- `role === "diagnostic-sidecar"`。
- `authoritative === false`。
- `writesProductionState === false`。
- 可随 step 前进以支持历史迁移探针，但不得写回 `world.grid`、`world.plates`、`world.stats` 或任何生产 geology-v2 字段。

检查工具必须验证这个契约，避免后续误把 sidecar 当成第二套生产核心。
## 23. 生产迁移入口标准与自动化执行

本章用于长期自动化重构。后续 agent 应按“小切片、强验证、干净提交、自动继续”的节奏推进，不需要每轮向用户确认。只有遇到不可自行解决的阻塞、重大兼容性取舍，或同一任务连续失败，才暂停并询问用户。

### 23.1 允许接入生产路径的入口标准

`cubed-sphere-production-grid-adapter` 只有同时满足以下条件，才允许进入某个生产模块：

- 该模块完全以 `cell id` 遍历，不依赖 `grid.width / grid.height / y * width + x`。
- 该模块所有邻接、洪泛、距离场、扩散和平滑都通过 topology graph API 完成。
- 该模块的统计指标使用 `area` 加权，不能用 cell count 直接代表面积。
- 该模块在 cylindrical 与 cubed-sphere 两种模式下都有接口检查或独立 regression check。
- 该模块能在 debug-render 中解释自己的关键状态，不只依赖最终地形肉眼判断。
- `index.html` 仍保持 classic script 和 file:// 双击运行，不引入默认 module-only 路径。

禁止接入条件：

- 模块仍然读取或写入矩形上下边界特殊逻辑。
- 模块仍把地图左右边缘当作唯一 wrap 规则。
- 模块把投影输出坐标反向作为模拟坐标。
- 模块在 cubed-sphere 下需要伪造 `width / height` 才能工作。
- 模块通过全局模糊掩盖 face seam，而不是在 graph 上实现连续传播。

### 23.2 下一轮生产迁移路线图

推荐把后续工作拆成以下可提交任务，每一项都必须独立验证并提交：

1. 只读诊断接入 adapter：让 stats、histogram、field summaries 支持 cubed-sphere adapter。
2. 连通性派生层接入 adapter：迁移 `externalSeaMask / oceanConnectivity / closedBasinId / inlandWaterCandidate`。
3. 距离场工具接入 adapter：统一海岸距离、边界距离、海岭/海沟距离的 graph 实现。
4. 局部平滑与扩散接入 adapter：提供 graph diffusion，不再依赖矩形 kernel。
5. 板块分配和边界分类接入 adapter：从诊断板块推进到可替代 cylindrical 的生产板块场。
6. 洋壳年龄与洋底高程接入 adapter：迁移 ridge birth age、age subsidence、ridge/trench terms。
7. 裂谷与闭合盆地接入 adapter：保证陆内裂谷不会因投影边界或面边界被硬切成规则海。
8. 沉积与盆地预算接入 adapter：使用面积加权和 graph transport，避免直线贴图残影。
9. 投影渲染层切换：equirectangular、orthographic 等投影只读采样同一个球面状态。
10. 默认 topology 切换评估：只有完整验收通过后，才考虑把默认 topology 从 cylindrical 改成 cubed-sphere。

### 23.3 最小可行实现版本

MVP 不要求一次性迁移完整地质系统。最小可行版本只需证明“生产状态可以生活在球面 graph 上，并被多个投影一致渲染”。

必做：

- cubed-sphere production adapter 字段契约。
- 面积加权统计。
- 球面 graph 连通性与 closed basin 识别。
- graph 距离场。
- spherical diagnostic terrain 与 debug render。
- cylindrical / cubed-sphere 双路径 interface-check。

可延后：

- 完整沉积搬运。
- 完整造山生命周期。
- 完整水文河网。
- GPU/WebGPU 球面 compute。
- 默认 UI 切换为 cubed-sphere。

只诊断不渲染：

- topology seam risk。
- area distortion risk。
- projection sampling risk。
- adapter rectangular dependency risk。
- spherical/cylindrical metric drift。

### 23.4 关键规则失败症状

后续每个检查失败时，应优先按症状定位，而不是直接扩大重构范围。

- `crustAge` 失败：海底年龄出现矩形色带、face seam 色带，或远离海岭仍有规则年龄贴图。
- `oceanConnectivity` 失败：低于海平面的内陆裂谷被当成外海，closed basin 数量异常为 0 或全图泛滥。
- `distanceField` 失败：海岸距离、边界距离在 face seam 处跳变，或跨面传播明显中断。
- `sediment` 失败：浅海被大片填陆，盆地边缘贴着网格/旧边界形成直色带。
- `riftStage` 失败：陆内裂谷瞬间变成规则海、扇形湖，或 proto ocean 不需要连通外海就转 young ocean。
- `transformMemory` 失败：739 Myr 仍有长直海底阴影，active 与 inactive boundary relief 区分不出来。
- `projectionRenderer` 失败：同一板块边界在不同投影下断裂、错位，或投影接缝被误认为模拟接缝。
- `areaWeighting` 失败：分辨率变化导致陆海比、板块覆盖率、盆地比例大幅漂移。
