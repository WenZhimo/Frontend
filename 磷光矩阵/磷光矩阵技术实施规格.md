# 磷光矩阵技术实施规格

本文档将《磷光矩阵视觉规范》转化为当前项目可执行的实施架构。

《磷光矩阵视觉规范》是唯一视觉依据。本文档不重新解释、不重新设计视觉语言，只定义如何在当前项目中实现该视觉规范。

本文档不包含生产代码、不包含样式代码、不包含 shader 代码。

## 1. 项目分析

当前项目是单文件静态网页，核心文件为 `index.html`。

### 前端框架

项目未使用前端框架。页面由原生 HTML、CSS 和 JavaScript 构成。

### 渲染模型

当前页面同时包含以下渲染来源：

- 普通 DOM 文本与布局
- CSS 样式和 CSS 变量
- 本地图片
- 通过 `<img>` 引用的 SVG
- HTML 视频
- Canvas 2D 动态画布
- Chart.js 生成的 canvas 图表
- 预留的全屏 canvas 覆盖层 `shaderMount`

### 构建系统

当前项目没有构建流程。浏览器可直接打开 `index.html` 运行。

### 样式架构

样式以内联 `<style>` 形式写在 `index.html` 中。全局变量集中在 `:root`，包括颜色、阴影和圆角等基础值。

当前样式是普通浅色网页基准，并非磷光矩阵视觉。

### 设计 token 系统

当前不存在正式设计 token 系统。已有 CSS 变量可作为未来视觉系统接入点，但不足以表达矩阵、发光单元、bloom、镜头扩散等视觉参数。

### 主题系统

当前页面只有浅色基准主题，没有主题切换系统。

### 动画系统

当前动画由原生 `requestAnimationFrame` 驱动，主要用于两个 Canvas 2D 示例：

- `orbitCanvas`
- `signalCanvas`

Chart.js 图表也有内部动画和交互更新。

### SVG 使用

页面通过 `<img>` 引用本地 SVG 文件：

- `../asset/img/logo.svg`
- `../asset/img/logo2.svg`

SVG 本身不作为主视觉系统的一部分，只是被滤镜处理的输入内容。

### Canvas 使用

当前页面使用多个 canvas：

- `orbitCanvas`：Canvas 2D 动态粒子与轨道。
- `signalCanvas`：Canvas 2D 信号网格。
- `lineChart`、`comboChart`、`doughnutChart`、`radarChart`：Chart.js 图表。
- `shaderMount`：预留的全屏视觉覆盖层。

### WebGL 使用

当前项目没有 WebGL 代码。

### 图像管线

图像资源通过普通浏览器资源加载机制直接引用，没有自定义预处理管线。

### 组件层级

页面为语义 HTML 结构，未抽象为组件系统。主要结构包括：

- 顶部导航
- 头图区域
- 摘要卡片
- 文章区域
- 数据表格
- 颜色块
- SVG 测试区
- Canvas 测试区
- Chart.js 图表区
- 视频区
- 表单区
- 预留滤镜接口区

### 可复用工具

当前已有的关键抽象为 `window.WebShaderTestHost`：

- `version`
- `target`
- `mount`
- `resize`
- `enablePreview`
- `disablePreview`

该对象是后续视觉系统最合适的接入点。

### 性能约束

页面包含动态 canvas、图表、视频和滚动内容。磷光矩阵效果若覆盖整页，需要考虑：

- 实时采样成本
- 高 DPR 设备成本
- bloom 多 pass 成本
- 移动端性能
- 页面滚动与 resize 同步
- 视频与 canvas 内容更新频率

### 可访问性策略

当前 DOM 是真实内容层。视觉覆盖层 `shaderMount` 设置为 `aria-hidden="true"`，且应保持不接管语义。

后续实施必须保留 DOM 作为可访问层，不能用 canvas 或 WebGL 视觉层替代真实内容。

### 浏览器兼容目标

最低可行目标应为支持 Canvas 2D 的现代浏览器。高保真目标应为支持 WebGL 的现代桌面与移动浏览器。

### 现有渲染抽象

`shaderMount` 已经具备作为全屏视觉覆盖层的基础结构。它固定在视口内，默认不显示，且 `pointer-events: none`。

该结构适合承载视觉滤镜层，但目前只绘制预览边界，不实现任何磷光矩阵效果。

## 2. 能力分析

下表将视觉规范中的关键要求映射到当前项目的实现能力。

| 视觉特征 | 分类 | 说明 |
| --- | --- | --- |
| 冷蓝白整体色彩 | Native / Hybrid | DOM 主题可近似，统一视觉应由覆盖渲染层控制 |
| 深黑背景 | Native | 可通过页面主题和覆盖层暗化实现 |
| 低光摄影感 | Canvas / WebGL | 需要暗部雾感、轻微噪声和柔焦叠加 |
| 独立发光单元 | Requires Canvas / Requires WebGL | 普通 DOM 或 CSS glow 不足以表达单元级发光 |
| 高密度正交矩阵 | Requires Canvas / Requires WebGL | 大量单元不适合用 DOM 节点实现 |
| 单元暗缝 | Requires Canvas / Requires WebGL | 需要在亮区内部仍保留格点结构 |
| 高光内矩阵可见 | Requires WebGL / Hybrid rendering | 需要控制 emission、bloom 和最终合成顺序 |
| 白热核心 | Requires Canvas / Requires WebGL | 可通过亮度映射和单元核心层实现 |
| 蓝紫外晕 | Requires WebGL | 多尺度扩散更适合 WebGL |
| 单元级 bloom | Requires WebGL | 必须从发光单元而非完整对象产生 bloom |
| 文字点阵化 | Hybrid rendering | DOM 保留语义，视觉层重建文字外观 |
| 波形离散采样 | Canvas / WebGL | 当前 canvas 内容可被采样后矩阵化 |
| 图形矩阵采样 | Hybrid rendering | DOM、SVG、canvas、视频统一作为输入源 |
| 摄影式柔焦 | WebGL / Canvas | WebGL 更适合实时高质量扩散 |
| 低强度噪声 | Canvas / WebGL | 可作为最后合成层 |
| 禁止 CRT 曲率 | Native constraint | 效果链中不得加入曲面变形 |
| 禁止 RGB 分离 | Native constraint | 效果链中不得加入彩边或通道偏移 |
| 禁止 VHS 故障 | Native constraint | 效果链中不得加入撕裂、雪花、信号损坏 |

## 3. 实施策略

### Option A：纯 CSS

优势：

- 简单
- 无额外渲染管线
- 易维护
- 对可访问性影响最小

限制：

- 无法可靠实现高密度单元矩阵
- 无法保证高光内矩阵可见
- bloom 容易变成普通数字 glow
- 无法统一处理 canvas、视频和 Chart.js 内容

结论：不适合作为主方案。

### Option B：CSS + SVG

优势：

- 可表达静态矩阵和少量矢量效果
- 比纯 CSS 更适合图形化发光
- 可维护性尚可

限制：

- 难以覆盖整页动态内容
- 难以处理视频与现有 canvas
- 高密度矩阵和单元级 bloom 复杂度高
- 文字、表格、表单等普通 DOM 需要额外映射

结论：可作为局部装饰方案，不适合作为全页视觉系统。

### Option C：Canvas 2D 重建

优势：

- 可实现矩阵量化
- 可实现基础 glow、噪声和暗场
- 能作为无 WebGL 环境的降级方案

限制：

- 多层 bloom 成本较高
- 高 DPR 下性能压力大
- 单元级光晕质量有限
- 全页实时采样和动态媒体同步复杂

结论：适合作为降级方案，不应作为最高保真主路径。

### Option D：WebGL 后处理

优势：

- 适合全页采样与图像处理
- 可高效实现矩阵化、bloom、扩散、噪声
- 适合多 pass 渲染
- 更容易维持高光中的矩阵穿透

限制：

- 实施复杂度更高
- 需要处理 WebGL 兼容性和资源生命周期
- 若替代 DOM，会损害可访问性

结论：适合作为视觉处理核心，但不能替代 DOM 层。

### Option E：Hybrid rendering

架构：

- DOM 保留为真实内容、布局、语义和交互层。
- `shaderMount` 作为视觉显示层。
- 视觉层采样页面目标区域。
- 视觉层将页面输入重建为冷蓝白磷光矩阵。
- DOM 不被删除、不被替换、不被遮断交互。

优势：

- 视觉保真度最高
- 可覆盖 DOM、canvas、图表、图片和视频
- 可保持可访问性
- 可通过质量档位渐进增强
- 与现有 `WebShaderTestHost` 接口契合

限制：

- 架构复杂度高
- 需要明确采样、同步和降级策略
- 需要严格性能预算

结论：选择 Hybrid rendering 作为主架构。

## 4. 系统设计

### DisplaySurface

职责：

- 管理 `shaderMount`
- 同步视口尺寸
- 处理 DPR
- 处理 resize
- 管理视觉层启停

依赖：

- `window.WebShaderTestHost.mount`
- `window.innerWidth`
- `window.innerHeight`
- `devicePixelRatio`

输入：

- 挂载 canvas
- 质量配置

输出：

- 已初始化的显示表面
- 当前显示尺寸
- 当前像素比例

生命周期：

1. 初始化 canvas 尺寸
2. 绑定 resize
3. 启动渲染循环
4. 停止时释放资源

### SourceSampler

职责：

- 从 `data-shader-target="page"` 采集视觉输入
- 统一 DOM、图片、视频、SVG、canvas 和图表来源
- 生成供后续矩阵化使用的源帧

依赖：

- `WebShaderTestHost.target`
- 当前滚动位置
- 当前视口尺寸
- 媒体加载状态

输入：

- DOM 目标节点
- 当前时间
- 当前视口状态

输出：

- `SourceFrame`
- 亮度可分析的源图像

约束：

- 不改变 DOM
- 不阻断交互
- 对跨源资源必须降级处理

### PixelMatrix

职责：

- 将源图像转化为规则正交矩阵
- 计算每个发光单元的亮度
- 保留单元之间的暗缝

输入：

- `SourceFrame`
- `matrixPitch`
- `cellFillRatio`
- `threshold`

输出：

- `CellField`

配置：

- 单元间距
- 单元填充比例
- 亮度阈值
- 最大亮度
- 暗部保留量

### CellRenderer

职责：

- 绘制单个发光单元
- 生成白蓝核心
- 保持单元边缘柔化
- 保持暗缝可见

输入：

- `CellField`
- 单元亮度
- 单元形状参数

输出：

- `EmissionBuffer`

### GlowEmitter

职责：

- 将单元亮度映射为发光强度
- 区分弱光、强光和白热核心
- 保证发光来自单元，而不是来自完整对象轮廓

输入：

- `EmissionBuffer`
- 发光曲线配置

输出：

- 单元级发光缓冲

### BloomRenderer

职责：

- 生成蓝紫外晕
- 处理多尺度扩散
- 保证 bloom 不吞掉矩阵结构

输入：

- 单元级发光缓冲
- bloom 半径
- bloom 强度

输出：

- `BloomBuffer`

约束：

- bloom 必须来自单元级 emission
- bloom 合成不能覆盖暗缝
- 不允许形成完整对象描边式 glow

### LensDiffusion

职责：

- 增加低光摄影式柔焦
- 生成轻微镜头扩散
- 软化边缘但不破坏矩阵

输入：

- emission 与 bloom 合成结果

输出：

- 摄影式显示帧

### DisplayTexture

职责：

- 管理暗部雾感
- 管理微弱显示介质感
- 提供深蓝黑背景层

输入：

- 当前画面亮度
- 黑位配置

输出：

- 暗场与介质纹理层

### NoiseGenerator

职责：

- 生成极轻暗部摄影噪声
- 避免画面过于数字干净

输入：

- 时间
- 噪声强度
- 暗部 mask

输出：

- 低强度噪声层

约束：

- 不生成 VHS 雪花
- 不生成故障撕裂
- 不生成彩色噪声主效果

### ThemeAdapter

职责：

- 将源页面映射到冷蓝白磷光色域
- 压低暖色和多彩 UI 颜色
- 维持主视觉单色体系

输入：

- 源帧颜色
- 亮度图

输出：

- 冷蓝白色彩映射

### AnimationController

职责：

- 管理渲染循环
- 控制帧率
- 处理页面可见性
- 根据质量档位降级

输入：

- `quality`
- 页面可见状态
- 当前性能状态

输出：

- 稳定帧调度

### AccessibilityAdapter

职责：

- 保证视觉层不接管语义
- 保证视觉层不阻断输入
- 保证 DOM 保持可读
- 管理降低运动偏好

输入：

- DOM 状态
- 用户系统偏好

输出：

- 可访问性约束状态

约束：

- 覆盖层保持 `aria-hidden`
- 覆盖层保持 `pointer-events: none`
- 键盘焦点仍属于 DOM

### VerificationHarness

职责：

- 定义视觉验收截图
- 检查矩阵可见性
- 检查高光穿透
- 检查性能
- 检查交互未被阻断

输出：

- 验收报告
- 截图证据
- 性能数据

## 5. API 设计

### 公共配置对象

公共配置对象用于控制视觉系统，但不暴露内部渲染细节。

#### `target`

类型：DOM Element  
默认：`window.WebShaderTestHost.target`

被采样的页面根节点。

#### `mount`

类型：HTMLCanvasElement  
默认：`window.WebShaderTestHost.mount`

视觉显示层 canvas。

#### `matrixPitch`

类型：number

发光矩阵的单元间距。数值越小，矩阵越密。该值必须保证单元在高光区域仍可辨认。

#### `cellFillRatio`

类型：number

单元在格子中占用的比例。该值控制暗缝可见度。不得设置为完全填满。

#### `coreIntensity`

类型：number

白蓝核心发光强度。过低会失去白热核心，过高会破坏矩阵穿透。

#### `bloomRadius`

类型：number

外晕扩散范围。必须足够柔和，但不能覆盖单元结构。

#### `bloomStrength`

类型：number

外晕强度。应服务于发光单元，而不是生成对象描边。

#### `diffusionStrength`

类型：number

镜头扩散程度。用于形成摄影式柔焦。

#### `blackLevel`

类型：number

暗场压低程度。必须让画面进入深蓝黑，而不是普通浅色网页。

#### `phosphorPalette`

类型：object

定义冷白、冰蓝、蓝紫、深蓝黑等色阶。不得包含绿色终端色或多彩霓虹色作为主色。

#### `noiseAmount`

类型：number

暗部摄影噪声强度。应极轻，不得成为视觉主题。

#### `motionMode`

类型：`static | realtime | powerSave`

控制渲染刷新策略。

#### `accessibilityMode`

类型：`preserveDom`

当前项目必须使用 `preserveDom`。不允许以视觉层替代 DOM 内容。

#### `quality`

类型：`low | medium | high`

控制矩阵密度、bloom pass、DPR 上限和采样频率。

### 内部 API

#### `sampleFrame`

输入：

- 目标 DOM
- 当前时间
- 视口状态

输出：

- `SourceFrame`

职责：

- 采集当前页面视觉输入

#### `buildLuminanceMap`

输入：

- `SourceFrame`

输出：

- `LuminanceMap`

职责：

- 计算可用于矩阵量化的亮度分布

#### `quantizeToMatrix`

输入：

- `LuminanceMap`
- 矩阵配置

输出：

- `CellField`

职责：

- 将连续亮度转换为离散发光单元

#### `renderEmission`

输入：

- `CellField`

输出：

- `EmissionBuffer`

职责：

- 生成单元级核心发光

#### `renderBloom`

输入：

- `EmissionBuffer`

输出：

- `BloomBuffer`

职责：

- 生成蓝紫外晕

#### `composeDisplay`

输入：

- `EmissionBuffer`
- `BloomBuffer`
- 显示纹理
- 噪声层

输出：

- 最终显示帧

职责：

- 合成摄影式磷光矩阵画面

## 6. 实施路线图

### Phase 1：接管显示层

目标：

- 使用现有 `shaderMount`
- 建立尺寸、DPR、resize 管理
- 建立启动与停止流程

验收：

- 覆盖层尺寸与视口一致
- DPR 变化后画面不拉伸
- 覆盖层不阻断交互

### Phase 2：建立页面采样管线

目标：

- 将 `data-shader-target="page"` 作为源区域
- 采样 DOM、图片、SVG、canvas、视频和图表

验收：

- 主要页面内容能进入视觉层
- 动态 canvas 和图表更新能被感知
- 不改变原页面 DOM

### Phase 3：建立冷蓝白色彩映射

目标：

- 将普通页面压入深蓝黑和冷蓝白体系
- 移除原页面多彩 UI 对主视觉的影响

验收：

- 画面主色为冷蓝白
- 暗场为深蓝黑
- 不出现绿色终端或赛博多彩倾向

### Phase 4：实现矩阵量化

目标：

- 将源亮度转化为规则正交矩阵
- 保留单元暗缝

验收：

- 文字、线条、图形都由矩阵单元构成
- 高亮和暗部都能看出统一矩阵逻辑

### Phase 5：实现单元级发光

目标：

- 每个单元具有核心发光
- 亮度随源内容变化

验收：

- 发光来自单元而不是对象轮廓
- 弱光偏蓝，强光接近白蓝

### Phase 6：实现 bloom 与镜头扩散

目标：

- 生成柔和蓝紫外晕
- 添加摄影式柔焦

验收：

- 外晕柔和
- 矩阵在高光中仍可见
- 不产生普通平面 glow

### Phase 7：加入暗部纹理与噪声

目标：

- 增加低光摄影感
- 避免过度数字干净

验收：

- 暗部有轻微雾感和噪声
- 不出现 VHS、故障或雪花感

### Phase 8：质量分级与性能优化

目标：

- 支持 `low`、`medium`、`high`
- 控制 DPR、矩阵密度、bloom pass 和采样频率

验收：

- 桌面高质量模式接近 60fps
- 移动端降级后保持稳定交互

### Phase 9：可访问性保护

目标：

- 保留 DOM 语义
- 保留键盘与指针交互
- 支持降低运动偏好

验收：

- Tab 顺序不变
- 表单可输入
- 视频控制可用
- 屏幕阅读器读取原 DOM

### Phase 10：视觉验证

目标：

- 建立截图和性能验收
- 对照视觉规范逐项检查

验收：

- 矩阵穿透高光
- 单元级发光成立
- 冷蓝白色彩成立
- 无 CRT/VHS/RGB 分离

## 7. 视觉追踪矩阵

| 视觉规范要求 | 实现模块 | 验证方法 |
| --- | --- | --- |
| 独立发光单元 | `PixelMatrix`, `CellRenderer` | 放大截图可见单元与暗缝 |
| 可见矩阵结构 | `PixelMatrix` | 全页面内容统一呈现矩阵采样 |
| 高光内矩阵可见 | `CellRenderer`, `BloomRenderer` | 高亮区域局部截图仍有格点 |
| 冷蓝白磷光 | `ThemeAdapter` | 主色采样不偏绿、不偏红紫 |
| 白热核心 | `GlowEmitter` | 峰值区域有白蓝核心 |
| 蓝紫外晕 | `BloomRenderer`, `LensDiffusion` | 外圈呈冷蓝紫柔散 |
| 摄影式柔焦 | `LensDiffusion` | 边缘柔化但不糊成无结构光团 |
| 深蓝黑暗场 | `DisplayTexture` | 背景接近深蓝黑，有低光感 |
| 轻微暗噪 | `NoiseGenerator` | 噪声低强度，不主导画面 |
| 文字点阵化 | `SourceSampler`, `PixelMatrix` | 文字边缘有矩阵采样痕迹 |
| 波形离散化 | `PixelMatrix` | 波形不是连续线 |
| 图形服从矩阵 | `SourceSampler`, `PixelMatrix` | SVG、图表、canvas 均进入矩阵系统 |
| 禁止 CRT 曲率 | `VerificationHarness` | 截图无屏幕弯曲或桶形畸变 |
| 禁止 RGB 分离 | `VerificationHarness` | 截图无彩边和通道错位 |
| 禁止 VHS 故障 | `VerificationHarness` | 截图无撕裂、雪花、磁带拖影 |
| DOM 可访问性 | `AccessibilityAdapter` | 键盘、表单、媒体控制正常 |

## 8. 风险分析

### 性能风险

全页实时采样、矩阵量化和多层 bloom 可能导致帧率下降。

缓解：

- 限制 DPR
- 使用质量档位
- 对静态区域缓存
- 降低移动端 bloom pass
- 页面不可见时暂停

### Canvas 2D 限制

Canvas 2D 可以近似矩阵，但高质量 bloom 和高光穿透控制较弱。

缓解：

- Canvas 2D 作为降级路径
- 高保真路径使用 WebGL

### WebGL 兼容风险

部分浏览器或设备可能禁用 WebGL。

缓解：

- 提供 Canvas 2D 降级
- 提供关闭视觉层的原页面模式
- 在初始化阶段检测能力

### DOM 采样风险

浏览器安全策略可能限制跨源图像、视频或 canvas 读取。

缓解：

- 优先使用同源资源
- 对不可采样内容降级为亮度占位
- 避免依赖跨源像素读取作为核心路径

### 可访问性风险

如果视觉层拦截交互，会破坏表单、按钮、视频控制和键盘导航。

缓解：

- 覆盖层必须保持 `pointer-events: none`
- 覆盖层必须保持 `aria-hidden`
- DOM 不得被删除或替换

### 视觉偏差风险

实现者可能误用 CRT、VHS、RGB 分离或赛博霓虹套路。

缓解：

- 在效果链中明确禁止曲率、彩边、扫描线、故障撕裂和多色霓虹
- 验证阶段必须对负面参考逐项检查

### 缩放伪影风险

不同 DPR 和 viewport 尺寸可能导致矩阵间距不稳定。

缓解：

- 矩阵间距应基于显示层像素稳定计算
- resize 后重新量化
- 避免 CSS 缩放导致矩阵变形

### HDR 与显示器差异风险

不同显示器会改变高光和黑位观感。

缓解：

- 避免依赖极端亮度
- 用相对亮度关系验证
- 保证矩阵结构优先于绝对亮度

## 9. 验证计划

### 视觉验证

必须完成以下检查：

- 主标题高亮处放大截图，矩阵格点仍可见。
- 波形或图表线条区域被离散单元采样，而非连续发光线。
- 最亮区域有白蓝核心，但不是纯白糊块。
- 外晕为冷蓝紫柔散，不出现红紫霓虹或彩虹边。
- 暗场为深蓝黑，并有轻微低光摄影质感。
- 小字更暗、更虚，但仍保持仪器式可读性。
- 整体画面像被拍摄到的物理发光矩阵，而不是普通网页 glow。

### 负面验证

不得出现以下现象：

- CRT 屏幕曲率
- 桶形畸变
- RGB 通道分离
- 彩边错位
- VHS 雪花
- 画面撕裂
- 磁带拖影
- 绿色终端主色
- 多色赛博霓虹
- 平滑矢量发光字

### 交互验证

必须确认：

- 链接可点击
- 按钮可点击
- 表单可输入
- 下拉框可操作
- 视频控制可用
- Chart.js 刷新按钮可用
- 页面滚动正常
- 覆盖层不拦截鼠标

### 键盘与可访问性验证

必须确认：

- Tab 顺序与原页面一致
- 焦点可见
- 屏幕阅读器读取 DOM 内容
- `shaderMount` 不进入可访问性树
- 降低运动偏好启用时可降频或停用动态效果

### 性能验证

目标：

- 桌面高质量模式接近 60fps
- 移动或低端设备可降级到稳定 30fps
- resize 不造成长时间卡顿
- 视频和 canvas 动态内容不会导致持续内存增长

### 完成标准

实施只有在以下条件全部满足时才可视为完成：

- 视觉结果符合《磷光矩阵视觉规范》的必需项。
- 每个视觉要求都有对应实现模块。
- 每个实现模块都有验证方法。
- DOM 可访问性未被视觉层破坏。
- 禁止风格均未出现。
- 性能达到目标或进入明确降级模式。
