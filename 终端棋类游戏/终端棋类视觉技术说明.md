# 终端棋类视觉技术说明

## 状态

- 状态：Accepted
- 日期：2026-08-12
- 参考实现：`点阵国际象棋终端`
- 适用范围：中国象棋、五子棋、跳棋等后续终端风格棋类项目

这份文档记录国际象棋项目中已经验证过的公共技术方案，重点是视觉层。核心原则是：页面虽然使用 `<canvas>` 承载最终输出，但它不是粒子画布，也不是普通 2D 图形界面，而是模拟一个固定尺寸的字符终端。棋盘、棋子、涟漪、拖尾、吃子崩解、右侧面板和控制提示都必须先落入字符缓冲区，再统一渲染到画布上。


主要实现集中在 `点阵国际象棋终端/app.js`：

- 终端尺寸与布局：`COLS`、`ROWS`、`left`、`right`、`board`
- 字符缓冲区：`screen.ch`、`screen.fg`、`screen.bg`
- Braille 子像素层：`dotLayer`、`DOT_W`、`DOT_H`、`BRAILLE_BASE`
- 棋盘纹理：`boardDensity`、`boardDither`、`boardDotMask()`
- 棋子形状：`buildPieceMasks()`、`pieceMasks`、`drawPieceAt()`
- 动态效果：`ripple()`、`trail()`、`shatter()`、`drawTerminalEffects()`
- 输出流程：`clearScreen()`、`drawBoard()`、`drawPieces()`、`flushDotLayer()`、`drawPanel()`、`render()`

## 视觉原则

- 深色终端背景是底层气质，界面应接近 TUI 或终端模拟器，而不是游戏 UI 皮肤。
- 所有可见主体必须落在固定字符网格内，不直接绘制任意圆点、SVG 棋子或 Canvas 粒子。
- 点阵字符是统一视觉语言。当前参考实现主要使用 Unicode Braille，因为一个字符天然包含 `2 x 4` 个可控子点。
- 棋盘格的明暗关系由稳定的纯色背景块承担，表层点阵只提供纹理密度。
- 棋子形状由 ASCII mask 转成 Braille 点阵，不使用 Unicode 棋子符号，也不使用普通字母代替棋子。
- 动态效果通过字符 mask、前景色、亮度、生命周期和位置变化实现，而不是叠加独立的图形特效层。
- 终端 UI 文案优先使用英文，当前字体环境下中文在终端画布内的观感不稳定。

## 终端渲染模型

参考实现使用固定的 `126 x 60` 字符坐标系。每个字符格保存三份数据：

```js
screen.ch // character
screen.fg // foreground color
screen.bg // background color
```

每帧渲染分两步：

1. 按字符格绘制背景矩形。
2. 按字符格绘制非空字符。

这样可以让视觉仍然受字符网格约束，同时利用 Canvas 获得稳定缩放、DPR 适配和浏览器兼容性。后续棋类项目应复用这个模型：先改棋盘坐标和棋子 mask，再接入规则与 AI，不要把视觉层改回自由绘图模型。

## Braille 子像素层

Braille 字符从 `0x2800` 开始，一个字符可以承载 8 个子点。当前约定：

```js
const DOT_W = 2;
const DOT_H = 4;
const BRAILLE_BASE = 0x2800;
```

写入流程：

1. 棋盘纹理、棋子和特效先写入子像素坐标。
2. `brailleBit(sx, sy)` 将子像素映射到 Braille bit。
3. 同一个字符格内的 bit 被合并为一个 8-bit mask。
4. `String.fromCharCode(BRAILLE_BASE + mask)` 生成最终字符。

`dotLayer` 是所有点阵视觉的中间层：

```js
dotLayer.mask  // 当前字符格的 Braille bit mask
dotLayer.power // 当前字符格的亮度/权重
dotLayer.fg    // 当前字符格的前景色
```

`flushDotLayer()` 只把棋盘区域内的 mask 刷入 `screen`，避免特效越过棋盘边界并污染右侧信息面板。

## 棋盘背景

棋盘背景由两层组成：

1. 纯色背景块：亮格和暗格使用固定背景色，负责清晰的棋盘格明暗关系。
2. 表层点阵纹理：所有格子的点颜色一致，当前为 `boardParticle`，只通过密度形成细腻差异。

参考实现使用固定的 `8 x 8` ordered dither 矩阵生成纹理：

```js
const boardDither = [
  [0, 48, 12, 60, 3, 51, 15, 63],
  ...
];
```

每个棋盘格先得到稳定密度等级，再通过 dither 阈值决定某个 Braille 子点是否点亮。这个方案解决了两个关键问题：

- 规则感：点阵看起来像终端字符拼接，而不是随机噪声。
- 稳定性：棋盘背景不会每帧随机跳动。

棋盘纹理约束：

- 背景纯色不随机变化。
- 点颜色统一，不给亮格、暗格或不同阵营使用不同背景点颜色。
- 任意相邻亮格的点密度高于相邻暗格。
- 全局允许某一处暗格比另一处亮格更密，用来保留自然变化。
- 点阵密度必须克制，不应盖住底层背景色。上限原则是不超过 70%，当前参考实现实际保持在更低的 `4%` 到 `17%` 区间。
- 密度可以由固定 hash、棋盘坐标和 dither 矩阵决定，但不能由每帧随机数决定。

## 棋子形状

棋子先用 ASCII mask 定义剪影，再转换为 Braille 子点。例如：

```js
pawn: [
  "      ####      ",
  "     ######     ",
  "     ######     ",
  ...
]
```

`buildPieceMasks()` 会把 mask 纵向扩展，让 Braille 的 `2 x 4` 子点比例更接近终端字符实际显示效果。`drawPieceAt()` 再把 mask 以棋盘格中心为锚点写入 `dotLayer`。

棋子设计原则：

- 每种棋子必须有独立剪影，至少能区分兵、车、马、象、后、王。
- 边缘可以降低 power 或使用辅色，形成轻微体积感。
- 同阵营内部可以有主色和辅色，但不要破坏阵营识别。
- 棋子点位不能每帧随机跳动。稀疏、缺口和内部层次必须由棋子 id、坐标和固定 hash 决定。
- 棋子必须视觉居中。中心应基于棋盘格中心和 mask 尺寸计算，必要时使用固定子像素偏移校正，而不是靠随机偏移。

当前国际象棋配色：

- 白方：亮白到浅青。
- 黑方：橙黄到金黄。
- 黑方移动和吃子特效：使用红色系，避免黄色特效干扰黄色棋子本体。

## 动态效果

所有动态效果仍然写入 Braille 子像素层，最后由 `flushDotLayer()` 转成字符。动态层只表达视觉，不直接改变规则状态。

### 移动

棋子移动使用连续插值：

```js
activeCharPosition(smooth(t))
```

AI 返回之后必须使用新的 `performance.now()` 创建动画。如果沿用开始思考前的旧时间戳，较慢引擎会让动画一创建就过期，表现为棋子瞬移。

### 涟漪

`ripple()` 记录中心、阵营、强度、出生时间和生命周期。绘制时按椭圆距离生成环状 Braille mask，并随时间降低亮度。它的观感应是字符点阵被冲击后短暂点亮，而不是独立粒子环。

### 拖尾

`trail()` 沿移动路径写入短生命周期碎片。碎片会扩散和淡出，但仍然通过 Braille 子点显示。

### 吃子崩解

`shatter()` 将目标棋子的点阵拆成短生命周期碎片。吃子、将军或将杀可以改变颜色、数量和强度，但仍应保持点阵字符语言。

### 复现边界

静态棋盘纹理和棋子形状应稳定复现。动态碎片如果需要像素级录屏复现，应由 move id、种子和固定事件序号派生随机数；如果只要求棋局复现，动态碎片可以不参与规则签名。

## 推荐渲染顺序

每帧推荐顺序如下：

1. `clearScreen()` 清空字符缓冲并绘制左右终端区域。
2. `drawBoard()` 写入棋盘纯色背景、棋盘点阵、坐标和状态提示。
3. `drawTerminalEffects()` 写入涟漪、拖尾、崩解碎片。
4. `drawPieces()` 写入静态棋子和正在移动的棋子。
5. `flushDotLayer()` 将 dot layer 转成 Braille 字符。
6. `drawPanel()` 写入右侧 MATCH / MATERIAL / MOVES 面板。
7. `render()` 把字符缓冲输出到 Canvas。

如果后续项目需要特殊高亮，例如五子棋五连线、中国象棋将军线或跳棋连跳路径，建议放在特效层和棋子层之间，并继续写入 `dotLayer`。

## 布局与响应式

CSS 负责外壳比例，Canvas 内部负责终端坐标：

```css
--terminal-ratio: 1.533;
.terminal-shell { aspect-ratio: 1720 / 1122; }
```

`resize()` 根据画布实际尺寸计算：

```js
cw = rect.width / COLS;
ch = rect.height / ROWS;
fontSize = Math.min(ch * 0.9, cw * 1.42);
```

后续项目建议：

- 保持固定字符坐标系，避免不同屏幕尺寸下重排逻辑。
- 棋盘变大或变小时优先改 `board` 配置，而不是直接改 CSS。
- PC 全屏、窄屏和移动端都要验证棋盘底部坐标、右侧面板和顶部 seed bar 不被裁切。
- 不要让棋盘渲染超过左侧区域边界；棋盘、坐标、状态文字都应被限制在 `left` 区域。

## 右侧信息面板

右侧信息面板也是终端缓冲区的一部分，不是 DOM 面板。国际象棋当前包含：

- MATCH：选手名称、胜场、模式、ply、move、当前状态。
- MATERIAL：材料差、优势数字和 Braille 进度条。
- MOVES：最近着法、颜色区分、滚动位置。
- Controls：速度、J/K 滚动、R reroll、结束后的 replay。

后续棋类可以保留结构，替换指标：

- 中国象棋：将军、吃子、重复局面、长将或自然限着。
- 五子棋：先后手、禁手、连珠威胁、最后落子。
- 跳棋：剩余棋子、连跳状态、升王数量。

## 游戏逻辑边界

视觉层不要直接依赖某一种棋类规则。推荐分为三层：

1. 规则状态层：棋盘、合法走法、胜负和局面重复。
2. AI / 对局层：选手、种子、超时、走法选择和模式。
3. 终端视觉层：字符缓冲、棋盘布局、棋子 mask、动画和面板。

国际象棋当前使用：

- `chess.js`：规则、FEN、合法走法和和棋判断。
- `js-chess-engine`：轻量 AI 选手。
- `stockfish.js` + Web Worker：Stockfish 选手。
- 本地 heuristic AI：提供不同棋风的轻量选手。

Stockfish worker 按对局/选手复用，避免每步重新加载 WASM。AI 单步超时为 `10s`，超时判负并记录原因。

## 种子与模式

当前有两种模式：

- Deterministic / Replay：同一种子应复现同一局。配对、启发式选择和可控随机都使用 seeded RNG。
- Full Engine / Live：保留引擎实时搜索和随机性，不承诺同一种子复现，只把种子作为开局标识和部分视觉/配对来源。

种子为固定 `100` 位 ASCII 字符，不足时用空格补齐。测试脚本可以批量生成种子并比较多次完整对局签名，用于验证 Replay 模式。

## 新棋类复用清单

创建新棋类项目时建议按这个顺序做：

1. 复制终端外壳、字符缓冲区、Braille dot layer 和 render loop。
2. 修改棋盘尺寸、坐标标签和 `board` 布局。
3. 设计新棋子的 ASCII mask 或落子 glyph。
4. 保留纯色背景块 + ordered dither 纹理方案。
5. 将规则状态封装为稳定的 board state。
6. 将走法标准化为 `{ from, to, side, flag }` 或该棋类等价结构。
7. 让动画只消费标准化走法，不直接理解规则。
8. 为 Replay 模式准备种子、对局签名和超时机制。
9. 用浏览器截图验证 PC 全屏、移动端、边界裁切和文本溢出。
10. 再逐步接入更强 AI 或更复杂规则。

## 禁止事项

- 不要直接用 Canvas 绘制粒子、圆点、线段或 SVG 棋子。
- 不要让棋盘背景点或棋子点每帧随机跳动。
- 不要把不同阵营颜色混入棋盘背景点。
- 不要让视觉效果直接修改规则状态。
- 不要在 `file://` 下依赖 Web Worker 或 WASM 引擎，应通过本地 HTTP 启动。
- 不要在终端画布内使用大段中文 UI 文案，除非先验证字体效果。

## 验证清单

- 棋盘、棋子、特效和面板都从字符缓冲区输出。
- 棋盘背景格有稳定纯色明暗，点阵只负责纹理。
- 背景点阵规则、克制、无帧间跳动。
- 棋子在格内居中，静态时无随机跳动。
- 移动动画连续，慢 AI 返回后不会瞬移。
- 吃子、拖尾、涟漪都保持 Braille 字符语言。
- 右侧信息面板不被棋盘覆盖。
- 全屏和移动端不裁切棋盘底部。
- Replay 模式同一种子可复现同一局。
