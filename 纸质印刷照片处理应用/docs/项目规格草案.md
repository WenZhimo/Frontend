# 项目规格草案

## 1. 项目一句话

做一款浏览器内运行的照片处理 Web 应用，让普通照片呈现接近纸质印刷物的质感。

它的重点不是普通复古滤镜，而是模拟真实印刷中的：

- 半调网点；
- 油墨叠印；
- 轻微套印偏移；
- 纸张颗粒和纤维；
- 细节损失和吸墨感；
- 留白、裁切和边缘不完美。

## 3. North Star

用户上传一张照片后，可以通过少量直观控制，把照片处理成具有纸张、油墨、网点和错版质感的印刷风格图片，并导出可分享的 PNG。

## 4. 第一版 MVP

第一版优先做到：

- 图片上传：支持文件选择、拖拽，后续可加粘贴。
- 实时预览：显示处理后的画布，参数变化后可重新渲染。
- 预设：提供 4-6 个默认印刷风格预设。
- 参数控制：强度、颗粒、纸张颜色、网点大小、网点角度、油墨偏移、对比度。
- 色彩模式：支持单色、双色、三色印刷感；CMYK 可后置。
- 导出：支持 PNG 导出。
- 本地处理：图片不上传服务器。

## 5. 非目标

第一版暂不追求：

- PDF 导出；
- 专业印前分色文件；
- 批量处理；
- 云端存储；
- 用户账号；
- 复杂图层编辑器；
- 完整移动端图片编辑体验；
- 与 tone 或任何参考应用的 UI / 素材复刻。

这些能力可以作为后续阶段候选项，但不能在第一版中默认扩大范围。

## 6. 用户体验原则

- 打开即是工具，不做营销落地页。
- 默认预设必须足够好看，用户不调参数也能得到可用结果。
- 参数命名要接近视觉结果，不要暴露过多算法术语。
- 高级参数可以折叠，避免第一屏复杂。
- 原图和处理结果之间应有清晰对比方式。
- 导出路径要短：上传、选择预设、微调、导出。

## 7. 推荐界面结构

```text
顶部栏
  项目名 / 导入 / 导出 / 重置

左侧栏
  预设列表
  纸张与油墨风格

中央区
  大画布预览
  原图 / 处理后对比

右侧栏
  参数控制

  图片尺寸
  导出尺寸
  渲染耗时
```

## 8. 技术方向

```yaml
preferredStack:
  build: Vite
  language: TypeScript
  ui: React
  renderingMvp: Canvas 2D + ImageData
  performance: OffscreenCanvas + Web Worker preview/export rendering
  futureRealtime: WebGL shader
  export: canvas.toBlob
```

技术选型后续可以根据用户新增的更具体目标调整；在没有相反要求前，推荐使用 Vite + React + TypeScript。

## 9. 图像处理管线

建议处理顺序：

1. 读取图片并标准化到工作画布。
2. 预处理亮度、对比度、饱和度、色阶。
3. 将图像映射到一组油墨通道。
4. 对每个油墨通道生成半调网点或颗粒图案。
5. 对不同油墨通道施加轻微 x/y 偏移。
6. 按油墨叠印方式合成通道。
7. 叠加纸张底色、纸纹、纤维、污点和吸墨感。
8. 可选加入留白、裁切边缘或轻微边缘不齐。
9. 输出预览画布或导出画布。

## 10. 第一版验收标准

第一版可被认为达到 MVP，如果满足：

- 本地能启动 Web 应用。
- 能上传一张普通照片。
- 能选择至少 4 个预设。
- 能通过参数看到明显视觉变化。
- 处理结果具有可见的半调网点、颗粒、纸张纹理和轻微错版。
- 能导出 PNG。
- 对空状态、非图片文件、大图至少有基本处理。
- 有基础浏览器冒烟验证。

## 11. 需要用户确认的问题

- 应用名字和视觉气质：日系纸品、zine、海报印刷，还是偏专业印前工具？
- 第一版是否移动端优先？
- 是否必须完全离线可用？
- 导出目标是社交分享图，还是可印刷文件？
- 算法优先真实印刷模拟，还是优先好看的艺术滤镜？
