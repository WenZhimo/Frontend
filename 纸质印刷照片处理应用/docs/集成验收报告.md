# 集成验收报告

日期：2026-08-19

## 1. 验收范围

本轮验收覆盖第一版 MVP 的核心链路：

- 打开本地 Web 应用；
- 空状态展示；
- 导入 `tests/fixtures/simple-still-life.svg`；
- 处理画布渲染；
- 处理后 / 原图 / 对比预览切换；
- 预设切换；
- 网点参数、墨点形状、纸张颜色和色彩通道数量调整；
- 预设只作为可见参数快捷起点，完整参数面板、动态通道数量和自定义预设保存；
- 当前预设参数与预览模式重置；
- PNG 导出；
- 非图片文件错误反馈；
- 大图降采样提示；
- 桌面左右侧栏独立滚动与窄屏布局检查。
- 五类轻量视觉 fixture 可访问、可上传、可渲染。
- 本机真实照片样本上传、渲染、基础色分层叠印网点和基础像素指标验证。
- 本机真实照片原图 / 处理后对照审阅页和 contact sheet 生成。
- 本机真实照片 × 默认预设矩阵审阅页和 contact sheet 生成。

## 6. 发现并修复的问题

### SVG fixture 上传失败

现象：

- 按 `docs/测试与样例图片约定.md` 上传 `simple-still-life.svg` 时，浏览器显示 `图片读取失败`。

原因：

- 原实现只使用 `createImageBitmap(file)` 解码图片；当前浏览器环境对该 SVG fixture 不稳定。

修复：

- 在 `src/app/App.tsx` 中增加 `HTMLImageElement.decode()` 回退解码路径。
- 普通位图优先走 `createImageBitmap`；失败时读取为 data URL 并用 `HTMLImageElement` 解码。
- 同步清理错误状态中的旧渲染耗时，避免 `请选择图片文件 · xxxms` 这类误导状态。
- 为大图导入增加降采样提示。

验证：

- 重新上传 `simple-still-life.svg` 成功，画布输出为 `960 x 640`。
- 上传非图片文件后状态为 `请选择图片文件`，不再附带旧耗时。
- 上传合成 `3000 x 2000` SVG 后状态提示降采样，预览画布输出为 `1200 x 800`。

## 8. 剩余风险

- 当前自动化使用本机 Chrome / Edge 可执行文件；如其他机器找不到浏览器，需要设置 `CHROME_PATH`。
- 真实照片样本现在已有本机 local-only 自动化覆盖，但未提交进仓库；换机器复现时需要重新放置样本或设置 `REAL_PHOTO_DIR`。
- 自动化指标只能证明画布非空、不透明、有基本颜色和亮度变化；最终“纸质印刷质感是否够好看”仍需要人工视觉判断。
