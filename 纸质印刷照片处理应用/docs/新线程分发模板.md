# 新线程分发模板

## 1. 使用边界

这份模板仅供用户明确授权创建独立 Codex 任务 / 新线程时使用。若当前系统、用户边界或会话目标未授权创建新线程，不要创建新任务；改为按同样模块边界串行执行，或先暂停确认。

如果新线程创建不可用、会打断当前工作流，或用户只要求修复计划/状态文件，不要自动分发任务。

创建、等待、读取或导航新线程前，必须先阅读 `docs/新任务线程调用经验.md`，尤其是：

- 可选字段要么省略，要么传合法值，不要传空字符串、空数组或空对象；
- `clientThreadId` 只表示异步准备中，不是正式 `threadId`；
- 第一次等待不要传空 `afterCursor`；
- 不要调用无关工具或 no-op 命令做探针。

## 3. M1 Product / UX 派发片段

```md
模块目标：

把“纸质印刷质感照片处理”翻译成第一版用户流程、参数结构、预设体验和验收点。

允许修改：

- `docs/项目规格草案.md`
- `docs/视觉验收清单.md`
- 新增 `docs/产品交互说明.md`，如需要

重点产出：

- 主流程；
- 参数分组；
- 控件命名；
- 默认预设描述；
- 空状态和错误状态；
- 第一版不做事项。
```

## 4. M2 Frontend Shell 派发片段

```md
模块目标：

搭建可运行的 Vite + React + TypeScript 应用外壳，完成上传、预览、参数面板和 mock renderer 接入。

允许修改：

- `package.json`
- `index.html`
- `src/app/*`
- `src/components/*`
- `src/styles/*`
- 与前端外壳直接相关的配置文件

禁止修改：

- `src/image-pipeline/*` 的真实算法实现，除非只是接入已冻结类型。
- `src/presets/*` 的最终 preset 定义，除非 M4 尚未交付时创建临时 mock。
```

## 5. M3 Image Pipeline 派发片段

```md
模块目标：

实现 Canvas/ImageData 图像处理管线，包括半调、颗粒、油墨映射、错版和纸纹叠加。

允许修改：

- `src/image-pipeline/*`
- 算法相关测试或 fixture

禁止修改：

- React UI 组件；
- 导出 UI；
- preset 产品命名，除非为了类型对齐提交建议。

重点约束：

- 算法接口应尽量纯函数化。
- 不依赖 React。
- 固定输入和固定 preset 应输出稳定结果。
```

## 6. M4 Presets / Textures 派发片段

```md
模块目标：

定义纸张、油墨、默认预设和纹理生成策略，让默认效果足够好看。

允许修改：

- `src/presets/*`
- `public/textures/*`
- `docs/视觉验收清单.md`

禁止修改：

- 渲染算法核心，除非提交接口需求给 M3。
- UI 布局，除非提交展示需求给 M2。
```

## 7. M5 Export / Performance 派发片段

```md
模块目标：

实现 PNG 导出，并设计预览尺寸、导出尺寸和大图处理策略。

允许修改：

- `src/export/*`
- `src/workers/*`
- 与导出按钮接入相关的最小 UI 文件
- 性能说明文档

重点约束：

- 导出应复用渲染管线。
- 不复制一套独立视觉算法。
- 大图必须有可解释的降级或等待策略。
```

## 8. M6 QA / Integration 派发片段

```md
模块目标：

验证应用从上传到导出的完整链路，并输出视觉验收和剩余风险。

允许修改：

- 测试文件；
- 验证脚本；
- `docs/视觉验收清单.md`
- `docs/集成验收报告.md`

禁止修改：

- 业务代码，除非是测试发现的小修复且主集成者明确允许。

重点验证：

- 打开应用；
- 上传图片；
- 切换预设；
- 调整参数；
- 导出 PNG；
- 空状态、非图片文件、大图；
- 桌面和窄屏布局。
```
