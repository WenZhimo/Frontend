# Codex 新任务/线程调用经验

## 1. 背景

当前环境里，旧式 `subagent / spawn_agent` 路径可能因为工具包装层参数序列化问题失败。常见问题是包装层自动带上空可选字段，例如：

- `items: []`
- `message: ""`
- `model: ""`
- `reasoning_effort: ""`
- `service_tier: ""`

这可能触发：

- `reasoning_effort must not be empty`
- `Provide either message or items, but not both`

如果需要并行或隔离执行，应使用 Codex 的“新任务 / 新线程”功能替代旧式内部子代理路径。新任务会出现在 Codex 侧边栏，是用户可见的独立任务，不是内部 subagent。

## 2. 不要做的事

### 不要传空可选字段

错误：

```json
{
  "model": "",
  "thinking": "",
  "title": "",
  "prompt": "...",
  "target": {}
}
```

可选字段要么完全省略，要么传合法值。不要用空字符串、空数组或空对象表示“省略”。

### 不要把 `clientThreadId` 当正式 `threadId`

`create_thread` 可能返回：

```json
{
  "clientThreadId": "client-new-thread:...",
  "hostId": "local"
}
```

这只表示任务 / worktree 正在异步准备中，不能直接用于：

- `wait_threads`
- `read_thread`
- `navigate_to_codex_page`

只有返回正式 `threadId` 时，才能直接等待、读取或导航。

### 不要给首次等待传空 `afterCursor`

错误：

```json
{
  "targets": [
    {
      "hostId": "local",
      "threadId": "...",
      "afterCursor": ""
    }
  ],
  "timeoutMs": 0
}
```

第一次等待时应完全省略 `afterCursor`。只有拿到上一轮返回的非空 cursor 后，下一次才传。

### 不要使用不存在的 projectless 目录

如果使用 projectless：

```json
{
  "target": {
    "type": "projectless",
    "directoryName": "thread-call-test"
  }
}
```

该目录必须真实存在，否则会报：

```text
Projectless thread directory must be a real directory
```

更稳妥的做法是先查已有项目，然后基于已有 project 创建线程。

### 不要用无关工具探针

不要为了“确认工具还能用”去调用：

- `read_thread_terminal`
- `load_workspace_dependencies`
- `navigate_to_codex_page` with dummy id
- `Write-Output 'no-op parallel check'`

这些会产生噪音，而且不能确认线程结果。

## 3. 推荐流程

### 先查项目

如果当前环境暴露项目查询工具，先查询项目列表，找到目标项目的：

- `projectId`
- `hostId`
- `isGitRepository`

如果项目是 Git 仓库，默认用 worktree；如果不是 Git 仓库，用 local。

示例项目：

```json
{
  "projectId": "local-f4b6ff9eeaa973be17a4320d0b749bcd",
  "label": "HTML",
  "path": "D:\\盒子\\HTML",
  "hostId": "local",
  "isGitRepository": true
}
```

### 创建线程

最小稳妥调用：

```json
{
  "prompt": "示例空任务：请只回复 OK，不读取、不修改任何文件，不运行命令。",
  "target": {
    "type": "project",
    "projectId": "local-f4b6ff9eeaa973be17a4320d0b749bcd",
    "environment": {
      "type": "worktree",
      "startingState": {
        "type": "working-tree"
      }
    }
  }
}
```

如果确实要指定模型、标题或推理强度，必须使用合法值：

```json
{
  "model": "gpt-5.6-luna",
  "prompt": "示例空任务：请只回复 OK，不读取、不修改任何文件，不运行命令。",
  "target": {
    "type": "project",
    "projectId": "local-f4b6ff9eeaa973be17a4320d0b749bcd",
    "environment": {
      "type": "worktree",
      "startingState": {
        "type": "working-tree"
      }
    }
  },
  "thinking": "low",
  "title": "线程调用测试"
}
```

不要传 `model: ""`、`thinking: ""`、`title: ""`。

### 判断返回值

如果返回正式 `threadId`：

```json
{
  "threadId": "...",
  "hostId": "local"
}
```

可以继续等待、读取或导航。

如果只返回 `clientThreadId`：

```json
{
  "clientThreadId": "client-new-thread:...",
  "hostId": "local"
}
```

说明任务还在异步创建 / worktree 准备中。不要把它当正式 `threadId` 使用。等待 UI 或任务列表产生正式线程 ID 后，再继续确认。

### 等待结果

第一次等待，不传 `afterCursor`：

```json
{
  "targets": [
    {
      "hostId": "local",
      "threadId": "正式-threadId"
    }
  ],
  "timeoutMs": 0
}
```

如果后续要继续等待，使用上次返回的非空 cursor：

```json
{
  "targets": [
    {
      "hostId": "local",
      "threadId": "正式-threadId",
      "afterCursor": "上次返回的非空cursor"
    }
  ],
  "timeoutMs": 30000
}
```

### 读取结果

如果等待工具不方便，或只有本地会话文件可查，可以从会话日志确认：

- 新任务 session 文件通常位于类似：
  `D:/Codex/.codex/sessions/YYYY/MM/DD/rollout-...jsonl`
- 查找 `client-new-thread`、任务标题、prompt 文本或正式 session id。
- 完成标志通常包含：
  - `phase":"final_answer"`
  - `task_complete`
  - `last_agent_message`

示例最终结果：

```text
正式会话 ID:
01a00466-9215-7e21-9a1b-946f03fb4955

最终回复:
OK

状态:
task_complete
```

## 4. 最简原则

- 创建线程：只传必填字段，或传合法可选字段。
- 确认线程：只用正式 `threadId`，不要用 `clientThreadId`。
- 第一次等待：不要传 `afterCursor`。
- 遇到 `clientThreadId`：表示异步准备中，先等它转成正式任务。
- 不要调用无关工具做探针。
- 不要传空字符串、空数组或空对象来表示“省略”。
- 新线程是用户可见的独立 Codex 任务；创建前应确认用户授权。
