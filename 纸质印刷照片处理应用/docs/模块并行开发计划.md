# 模块并行开发计划

## 1. 使用方式

这份文档供滚动目标模式和后续新线程分发使用。它定义模块边界、并行顺序、交付物、验收方式和集成约束。

如果用户明确授权创建新线程，主集成者可以按本文件拆分任务并并行派发到独立 Codex 任务 / 新线程。创建、等待或读取新线程前，必须先阅读 `docs/新任务线程调用经验.md`。如果当前会话未授权创建新线程，则按同样模块边界串行执行。

## 2. 主集成者职责

主集成者始终负责：

- 读取用户最新目标、项目计划和 `.agent/current-goal.md`。
- 冻结共享类型、目录结构和模块接口。
- 分发模块任务并限制范围。
- 合并各模块结果。
- 解决跨模块冲突。
- 运行最终验证。
- 更新 `.agent/current-goal.md`。
- 不让新线程交付结果自行改变项目 North Star、Desired State 或 Phase Goal。
- 遵守新线程调用经验：不传空可选字段，不把 `clientThreadId` 当正式 `threadId`，不使用无关工具探针。

## 3. 推荐阶段

### Phase 0：目标接入

目标：读取详细目标文件，形成正式项目规格和模块工作包。

输入：

- `粗略计划.md`
- `.agent/current-goal.md`
- `docs/项目规格草案.md`
- 用户稍后提供的详细目标文件

输出：

- 更新后的项目规格；
- 更新后的模块计划；
- 第一轮 Work Packet；
- 是否启用新线程并行的判断。

停止条件：

- 详细目标文件缺失；
- 目标中出现互斥产品方向；
- 技术栈、数据路径、发布方式或不可逆架构方向需要用户确认。

### Phase 1：架构冻结

目标：建立所有模块共享的最小接口和目录结构。

输出：

- `src/image-pipeline/types.ts`
- `src/presets` 配置结构；
- UI 与渲染管线的调用协议；
- 导出模块接口；
- 测试和样例图片约定。

建议共享类型：

```ts
export type InkLayer = {
  id: string;
  name: string;
  color: string;
  opacity: number;
  angle: number;
  offsetX: number;
  offsetY: number;
};

export type PaperProfile = {
  id: string;
  name: string;
  baseColor: string;
  grainAmount: number;
  fiberAmount: number;
  stainAmount: number;
};

export type HalftoneSettings = {
  enabled: boolean;
  dotSize: number;
  spacing: number;
  angle: number;
  contrast: number;
};

export type GrainSettings = {
  amount: number;
  scale: number;
  softness: number;
};

export type MisregistrationSettings = {
  amount: number;
  randomize: boolean;
};

export type PrintPreset = {
  id: string;
  name: string;
  description: string;
  inks: InkLayer[];
  paper: PaperProfile;
  halftone: HalftoneSettings;
  grain: GrainSettings;
  misregistration: MisregistrationSettings;
};

export type RenderInput = {
  image: ImageBitmap | HTMLImageElement | HTMLCanvasElement;
  preset: PrintPreset;
  size: { width: number; height: number };
};

export type RenderOutput = {
  canvas: HTMLCanvasElement | OffscreenCanvas;
  metadata: {
    width: number;
    height: number;
    renderMs: number;
    presetId: string;
  };
};
```

### Phase 2：并行实现

目标：各模块按共享接口并行推进。

并行模块：

- M1 Product / UX
- M2 Frontend Shell
- M3 Image Pipeline
- M4 Presets / Textures
- M5 Export / Performance
- M6 QA / Integration

### Phase 3：集成和验收

目标：合并模块、修复接口冲突、执行浏览器验证和视觉验收。

输出：

- 可运行应用；
- 通过基础冒烟测试；
- 可导出 PNG；
- 视觉验收报告；
- 更新后的 `.agent/current-goal.md`。

## 4. 模块工作包

### M1：Product / UX

目标：把纸质印刷质感转成用户可理解的界面、参数和预设。

任务：

- 定义主流程：上传、选择预设、微调、对比、导出。
- 定义参数分组：Paper、Ink、Halftone、Grain、Misregistration、Export。
- 定义控件名称和默认值。
- 定义 7 个默认预设。
- 定义空状态、错误状态、大图状态。

输出：

- 产品流程说明；
- 控件清单；
- 预设体验说明；
- 验收点。

验收：

- 每个控件都能映射到 `PrintPreset` 或渲染参数。
- 用户不需要理解算法术语也能操作。
- 不新增第一版非目标。

### M2：Frontend Shell

目标：建立可运行的 Web 应用外壳。

任务：

- 初始化 Vite + React + TypeScript。
- 实现上传、拖拽、画布预览。
- 实现预设列表和参数面板。
- 实现原图 / 处理后对比入口。
- 接入 mock renderer，等待 M3 替换。

输出：

- 可运行前端项目；
- 基础布局；
- 参数状态管理；
- 与渲染管线的接口调用。

验收：

- `npm run dev` 可启动。
- 上传图片后可以显示预览。
- 切换预设或参数会触发重渲染。
- UI 不直接实现像素算法。

### M3：Image Pipeline

目标：实现核心纸质印刷视觉算法。

任务：

- 标准化输入图片到 Canvas/ImageData。
- 实现亮度、对比度、饱和度和色阶压缩。
- 实现单色、双色、三色油墨映射。
- 实现 AM halftone：点距、角度、点大小、阈值。
- 实现 Grain 模式：噪声、纸面吸墨、细节损失。
- 实现 misregistration：各油墨通道轻微偏移。
- 叠加纸张纹理和油墨合成。

输出：

- `src/image-pipeline` 模块；
- 纯函数或近似纯函数处理接口；
- 固定 preset 的稳定输出。

验收：

- 固定输入和固定 preset 输出稳定。
- 参数变化有可见差异。
- 至少可见网点、颗粒、纸纹、错版四类效果。

### M4：Presets / Textures

目标：让应用默认效果好看，并把风格配置从算法中解耦。

任务：

- 定义纸张 Profile：米白纸、新闻纸、再生纸、冷白纸、暖黄纸。
- 定义油墨色板：黑、印刷青、印刷品红、印刷黄、深蓝、朱红、孔雀蓝、芥末黄、墨绿。
- 定义默认预设：Soft Paper、Riso Bloom、现实彩印、褪色彩印、Newspaper Dot、Mono Grain、Warm Poster。
- 设计程序化纸纹：低频云雾噪声、高频纤维噪声、轻微污点。

输出：

- `src/presets` 配置；
- 纸张和油墨 profiles；
- 纹理生成函数或静态资源规范。

验收：

- 每个 preset 都能被 UI 加载。
- 配置通过 TypeScript 类型检查。
- 不把 preset 硬编码进渲染算法。

### M5：Export / Performance

目标：保证导出可用，且大图处理不永久卡住 UI。

任务：

- 实现 PNG 导出。
- 支持预览尺寸和导出尺寸分离。
- 设计大图降采样策略。
- 接入 Worker / OffscreenCanvas，预览和导出渲染不阻塞 UI 交互线程。
- 输出基础性能预算。

输出：

- `src/export` 模块；
- 导出按钮接入；
- 性能策略说明。

验收：

- 导出 PNG 与预览结果一致或可解释地接近。
- 大图有明确尺寸限制或处理提示。
- 导出失败有用户可见反馈。

### M6：QA / Integration

目标：验证应用从上传到导出的完整链路。

任务：

- 编写浏览器冒烟测试或手动验证脚本。
- 检查上传、预设切换、参数调整、导出。
- 检查空状态、非图片文件、大图。
- 做桌面和窄屏布局检查。
- 根据 `docs/视觉验收清单.md` 输出视觉验收结果。

输出：

- 测试脚本或验证清单；
- 集成验收报告；
- 剩余风险列表。

验收：

- 应用主流程可跑通。
- 没有明显布局重叠或核心按钮不可用。
- 视觉结果符合第一版最低印刷感要求。

## 5. 并行顺序

```text
主集成者
  -> Phase 0: 读取详细目标文件
  -> Phase 1: 冻结共享类型和目录
  -> 并行 M1 + M2 + M3 + M4
  -> 集成 M2 + M3 + M4
  -> 并行 M5 + M6
  -> 最终集成和验收
  -> 更新 current-goal.md
```

## 6. 集成规则

- 共享类型由主集成者冻结，模块不得擅自改变。
- 如果模块必须改接口，应在交付摘要中声明，不要直接扩大影响面。
- 算法模块不依赖 React。
- UI 模块不直接写像素处理逻辑。
- 预设模块只输出配置和资源，不嵌入 UI 行为。
- 导出模块复用渲染管线，不复制独立视觉算法。
- QA 模块不改变产品范围，只验证已授权目标。
